## 第0章 目的・方法・出典

### 0.1 依頼と範囲

実装済みカードについて、**コードの正しさではなく、効果そのものの解釈が文献（ルールと裁定）に合っているか**を照合する。
対象は「分類をもとに実装されたカード」、すなわち次の合計 **75枚**。

| 由来 | 枚数 | 内容 |
|---|---:|---|
| PR #377（全840枚の分類確定版）で「実装済」 | 65 | `docs/all-cards-classification-final.md` 第4章の段階欄が「実装済」の行 |
| A008 食材かご | 1 | #377 の分類表では段階外のまま。実装は PR #359 で修正済み |
| PR #378（EndGameBonus 4枚） | 4 | D032 / D034 / E034 / E035 |
| PR #379（AfterOccupationGain） | 1 | C068 |
| PR #381（AfterAnyWorkerGain） | 4 | C141 / A050 / B064 / D061 |
| 合計 | **75** | 帯別: A 29 / B 21 / C 8 / D 8 / E 9 |

同定の機械照合: `src/cards.rs` に現れるカードIDリテラル（テスト内の参照を除く定義・登録）は
75件で、上の集合と**完全一致**した（重複0・欠落0）。#377 の65枚に A008 と #378/#379/#381 の9枚を
加えた75枚が、現在の `main` で実装済みとする集合である。

> 補足: `data/bga-card-base-ledger.csv` の `implementation_status` は75枚のうち大半が
> `not_started` のままで、コードの実装状況と一致しない（第6章 S-14）。本照合の対象同定には
> 台帳の実装列を使わず、コードの定義と #377 の分類表を使った。

### 0.2 照合の方法

1枚ごとに次の3つを突き合わせ、**仕様データの読み**が文献と合うかを見た。

1. 仕様データ `data/bga-card-specs/<ID>.json` の `play`（費用・前提・印刷点）と `effects`（トリガー・条件・手順・頻度・時点）
2. 文献の効果文（日本語の個別ページ、英語の一覧）と、ページ内の寸評・コメントにある裁定
3. 実装 `src/cards.rs` / `src/card_events.rs` / `src/engine.rs`（**読むだけ**。修正しない）

条件の範囲（いつ・誰に・何回）、端数の処理、他プレイヤーが関わる部分を厚く見た。
仕様JSONが存在しないカードは、実装の読みを「仕様側の読み」として扱い、その旨を表に明記した。

### 0.3 出典の等級

| 出典 | 等級 | 使い方 |
|---|---|---|
| 2016年改訂版 Lookout 公式ルール | A | フェイズ・得点・用語の前提。**カード固有の裁定は含まない** |
| `data/bga-card-base-ledger.csv` / `data/bga-card-specs/*.json` | B | 照合される側（リポジトリ内データ） |
| BGAアグリコラカード情報wiki 日本語個別ページ（`?p=NNNN`） | C | 効果文・費用・前提・寸評。BGA向けの二次情報 |
| 同wiki 英語一覧（`/cardlist_en/`） | C | 効果文の言語間クロスチェック。同一サイトであり独立2情報源ではない |
| ページ内コメント（利用者による裁定・経験談） | D | 公式裁定ではない。範囲の解釈を補う参考にとどめる |

**カード固有の公式FAQ・公式裁定文書は今回確認できていない。** したがって本文の「文献」は
主に等級Cで、等級Dのコメントは「コミュニティの裁定」と明記して使う。
公式裁定が見つかった論点は第7章の質問に残し、こちらで確定しない。

### 0.4 判定の区分

| 判定 | 意味 |
|---|---|
| 一致 | 仕様データの読みが文献と実質同じ |
| 仕様の表現不足・欠落 | 解釈は同じだが、仕様データが文献の条件・範囲を表しきれていない（述語の語彙不足、注記の欠落、JSON未作成など） |
| 食い違い | 条件の範囲・対象・端数の読みが文献と異なる |
| 文献で未確定 | 文献側でも扱いが割れる、または公式裁定が確認できない |

「仕様の表現不足」は**効果解釈の誤りではない**が、実装がその述語を字面どおりに解釈すると
食い違いになるため、区別して残す。

### 第A章の要点

- **A088 生け垣管理人**: 仕様は `worker_space_used(fence_building)` で「柵の建設スペースを使った時」に限定する。
  日本語ページの寸評は「柵のアクションスペースではなく、『柵の建設』のアクションで発動。
  カードで得た柵建設（腹心の友・猟師の囲い）や改築柵マスでも発動する」と明記している。
  実装は `free_fence_wood` を柵建設の共通経路で消費するため文献側に近い。**仕様の条件が狭すぎる**。
- **A101 調理器具商**: 仕様の `cooking_improvements` が何を指すか定義されていない。実装の `Improvement::is_cooking`
  は暖炉2種と調理場2種のみ。文献は掘り土窯・東洋かまども加点対象とする。**対象集合が実装で狭い**。
- **A005**: 効果の読みは一致するが、仕様JSONの費用が `null` のまま。台帳・文献とも飯1。
- **A119**: 仕様JSONが無く、実装の読みだけで照合した。効果自体は文献と一致。
- A042/A080/A116/A119 の「累積スペース」は、2人戦で存在しないスペースを含む集合（森林/小森/林、東西の採石場）で
  定義されている。人数による存在差は仕様側の注記がなく、実装は該当スペースが盤面に無ければ発火しないため実害はない。
