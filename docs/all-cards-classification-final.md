# 全カード分類 確定版（帯内636枚＋帯外204枚）

## 第0章 この文書の位置づけ

### 0.1 目的と範囲

- 対象リポジトリ: `cueikusuta/agricola-re-ai`。ルールの正本は2016年改訂版 Lookout 公式ルール。
- 目的: 段階1〜4の分類から外れていた帯外 **A/C/D/E 070〜120** を、帯内636枚と同じ形式で分類し、
  **帯内636枚＋帯外204枚＝840枚を1つの分類表**に統合する。
- 統合元:
  - **PR #370**（`research/deepai-allstages-merged`）: 帯内636枚の分類・段階定義・基盤記号。
  - **PR #376**（`research/deepai-outband-classification`）: 帯外204枚の分類・実装準備・残件。
  - **PR #375**（`research/freebuff-outband-sources`）: 帯外204枚の文献裏取りと独立分類。
- 本PRは**文書のみ**。`src/`・`data/`・`tests/` は変更しない。マージしない。

### 0.2 出典の等級と独立性

| 出典 | 等級 | 本統合での使い方 |
|---|---|---|
| 公式ルール（2016 RE） | A | フェイズ・段階・得点の前提 |
| `data/bga-card-base-ledger.csv`（台帳） | B | ID・種別・費用・前提・印刷点の正本 |
| `data/bga-card-specs/*.json`（仕様JSON） | B | 効果の構造（帯内495枚＋帯外59枚） |
| 第三者のBGAアグリコラカード情報wiki（日本語個別ページ、英語一覧） | C | 効果文の照合。同一サイトの言語差であり独立2情報源ではない |
| #370 の分類・段階定義・基盤記号 | B | 形式の継承 |
| #376 / #375 の分類 | B（二次整理） | 突き合わせ対象。原典ではない |

- カード原文・画像・PDFは保存しない。効果は**自分の言葉の要約**だけを置く。
- #375 は #370 の分類を追認も反駁もしていない独立整理である。本統合は両者を原典（台帳・仕様・wiki）に
  照らして裁定し、**どちらかを無条件に正としない**。

### 0.3 継承した段階定義と判定順

#370 §0.2〜0.4 をそのまま使う。新しい段階・記号は作らない。

| 段階 | 定義 |
|---|---|
| 段階1 | 費用が「A または B」の支払い候補の選択になっている |
| 段階2 | 他人の手番で発動する／カードが全員用スペースになる／カードが畑になる |
| 段階3 | 帰宅フェイズに発動・条件がある／部屋（建設・数・種類・収容・得点）または住居スロットが効果の条件・対象・発生源 |
| 段階4 | 異なる発動サイトを2つ以上またぐ、または1つのサイトで3操作系以上 |
| 段階外 | 単一サイト・単一操作で、4段階の基盤に依存しない（＝実装しない、ではない） |

判定は **段階1 → 2 → 3 → 4 → 段階外** の順で行い、最初に該当した1つにだけ割り当てる。
重なりは分類表の「区分・根拠」に注記し、二重計上しない。**実装済**は #370 と同じく段階とは別の区分とし、
分類表の段階欄には「実装済」と書く（下段の段階は注記する）。

**判定の単位（#370 の機械判定の明文化）**

1. サイト＝仕様JSONの `effects[].trigger` に相当するイベント種別。効果がフェイズそのものを実行する場合は、
   そのフェイズも1サイトとして数える。
2. 常時の軽減・払い戻しは「常時」1サイトとして数える。対象アクションが複数でも段階4にしない。
3. カードがアクションスペースになること自体は共通機構に乗せる。そのカードの主軸判定では個性として
   数えない。個性は「使用回数」「累積」「他者の支払い」の側で判定する。
4. ラウンド予約は「予約を置くサイト」と「ラウンド開始に取り出すサイト」の2サイトとして数える
   （#370 P7）。ただし段階3の条件（家の種類・部屋・帰宅）を先に満たす場合は段階3を採る。

### 0.4 依頼で確定済みの扱い（#370 から継承）

1. **OR費用は「支払い候補の選択」**として段階1。資源の選択とは呼ばない。進歩を返して出すカード
   （A060）や、家畜を返す／調理して払うカード（D082）も同じ入口に置く。
2. **アクションスペースを増やす効果は共通機構**として扱い、そのカードの個性として数えない。
3. **帰宅フェイズに関わる効果は段階3**（帰宅の基盤待ち）。any-player 等他の軸を持つ場合は重なりとして記録する。

### 0.5 基盤記号

#370 §4.1 の **PS / TR-SITE / TR-PHASE / SC / DEC / DEF / LOG / RH / ROOM / STACK** と
「占有フィルタ」をそのまま使う。本統合だけの追加記号は無い。

| 記号 | 意味 |
|---|---|
| PS | プレイヤー状態（カード上の在庫・使用回数・予約・フラグ） |
| TR-SITE | 発動サイト（出したとき／スペース使用／収穫フェイズ／ラウンド開始など） |
| TR-PHASE | フェイズ内の位置（Before / After） |
| SC | 対象範囲（自分／他者／全員） |
| DEC | プレイヤーの選択（対象・順序・任意） |
| DEF | 静的な定義表（対応表・上限・軽減） |
| LOG | 再演用の記録（選んだ費用・対象） |
| RH | 帰宅フェイズ |
| ROOM | 部屋・住居スロット・家の種類 |
| STACK | カード上在庫（順序つきを含む） |

### 0.6 分類表の読み方

- 第4章の表は **840枚を1つの論理表**とし、デッキ（A〜E）で区切って掲載する。
- 列は `ID / カード / 段階 / 区分・根拠 / 必要基盤 / 出典`。
- 帯内636枚の「区分・根拠」は #370 §3.1 の記載をそのまま使う。帯内は #370 が基盤列を持たないため
  「必要基盤」は `—` とする。
- 帯外204枚は、#376 の区分と #375 の必要基盤を突き合わせ、第3章の裁定を反映した最終値を載せる。
  出典は #375 の `p=` と #376 の章を併記する。
- 段階欄の `2関連` は #370 の区分（段階2の関連。カード畑・条件付き）をそのまま残したもの。

### 0.7 本PRで決めないこと

- 公式ルールの新解釈。文献で決まらない事項は第7章の質問に残す。
- 帯内636枚の分類の変更。帯内側で見つけた疑義は付録Cに「帯内側の再確認候補」として記録し、

## 第1章 対象範囲の確定（依頼の211枚 → 正本は204枚）

### 1.1 三者（台帳・仕様JSON・wiki）の一致

| 確認 | 結果 |
|---|---|
| 台帳 `data/bga-card-base-ledger.csv` | **840行**（5デッキ×168）。IDの重複0・欠番0 |
| 台帳の A/C/D/E 070〜120 | **204枚**（各51枚）。IDは各デッキで070〜120の連番 |

| wiki 英語一覧 `cardlist_en` | 帯内のIDは各デッキ51枚で台帳と一致（スクレイプ上の一意IDは838。Dの2枚はページ整形で拾えないが、070〜120は51枚そろう） |

  分類の対象範囲を変えない（BAN・版差はメタデータ）。

### 1.2 840枚の完全分割（204枚が上限であることの証明）

#370 の636枚と帯外204枚は、同じ840枚を**重複なく2分割**している。

| デッキ | #370 の対象（001〜069・121〜168） | 帯外（070〜120） | 合計 |
|---|---:|---:|---:|
| A | 117 | 51 | 168 |
| B | 168 | 0 | 168 |
| C | 117 | 51 | 168 |
| D | 117 | 51 | 168 |
| E | 117 | 51 | 168 |
| **合計** | **636** | **204** | **840** |

- #370 の表に 070〜120 のIDは1つも無い。
- 帯外204枚のIDに、070〜120の外のIDは1つも無い。
- したがって `636 + 204 = 840` は**全カードの完全被覆**であり、帯外に7枚を足す余地は
  「#370 に含まれるカードを帯外へ二重計上する」以外に存在しない。

### 1.3 差の7枚の同定

依頼の211枚と実データ204枚の差 **+7** について、台帳上で「7枚」と一致する集合を総当たりした。

| 候補 | 枚数 | 内訳 | データ上の所在 | 211への加算としての判定 |
|---|---:|---|---|---|
| **BAN=strong** | **7** | A082, A097, C099, C102, D074, D092, D097 | **204枚の中** | **二重計上。加算不可** |
| B070〜B076 | 7 | B070, B071, B072, B073, B074, B075, B076 | #370 の B168 の中 | 二重計上。加算不可 |
| A070〜A076 | 7 | A070, A071, A072, A073, A074, A075, A076 | #370 の A117 の中 | 二重計上。加算不可 |
| 各デッキの121〜127 | 7×4 | 4デッキ分で28枚 | #370 の各117の中 | 7枚にはならない |
| 費用が `unknown` | 4 | D080, D082, D083, E075 | 204枚の中 | 7枚にならない |
| 仕様JSONが無い | 145 | A1/C47/D46/E51 | 204枚の中 | 7枚にならない |
| 実装済みで仕様JSONが無い | 13 | A119 ほか（第6章） | 204枚の中 | 7枚にならない |
| 帯外の追加公式カード | 0 | — | 台帳・wiki・仕様のいずれにも無い | 存在しない |

**同定結果**

- 台帳が「7枚」という単位で別掲できる集合は **BAN=strong の7枚**だけである。
  `A082 / A097 / C099 / C102 / D074 / D092 / D097`。
- この7枚は**すでに204枚の中に含まれる**。依頼の211枚が「204枚＋BAN強7枚」の形で作られたなら、
  差の7枚はこの7枚の**二重計上**であり、204枚の外に別のカードがあるわけではない。
- 別の読み方として、B070〜B076 や A070〜A076 のような「隣接帯の7枚」を混入させた場合も、
  それらは #370 の636枚に含まれる。**どちらの読み方でも、204枚の外に7枚の実カードは存在しない。**
- したがって「204枚から対象外に落ちた7枚」は **0枚**。211は204の外側ではなく、
  204の内側の7枚を余分に数えた値である。

### 1.4 対象の正本

**正本: 台帳 `data/bga-card-base-ledger.csv` の A/C/D/E 070〜120、204枚。**

| デッキ | 正本のID範囲 | 枚数 |
|---|---|---:|
| A | A070〜A120 | 51 |
| C | C070〜C120 | 51 |
| D | D070〜D120 | 51 |
| E | E070〜E120 | 51 |
| **合計** | | **204** |

今後の枚数確認は次の3条件を同時に満たすこととする。

1. 各デッキの帯外枚数は `120 - 70 + 1 = 51`。
2. `#370の636 + 帯外204 = 840`（台帳の全行数）。
3. 帯外IDは070〜120の外に出ない。帯内IDは070〜120に入らない。

### 1.5 「対象から外れた7枚」への回答

- **外れたカードは無い。** 204枚が帯外の全体であり、211はそのうち7枚を二重に数えた値である。
- 依頼側が別の名簿（版差・別デッキ・プロモ等）を意図していた場合は、その名簿の提示が必要になる。
  ただし本リポジトリの正本（台帳840枚）とwikiには、A/C/D/E 070〜120 の外に該当7枚は存在しない。
- 旧 `BQ-0` / `Q-0`（204か211か）は**これで解決**とし、質問チェックリストから外す。

### 1.6 検算（再現手順）

```sh
# 台帳の全行数とデッキ別枚数

# => 168 A / 168 B / 168 C / 168 D / 168 E（合計840）

# => 204
```

- #370 の分類表は一意636（A117/B168/C117/D117/E117）、070〜120の行は0。
- 帯外204枚のID突合は第4章の表と付録Aで、重複0・欠番0を確認した。

## 第2章 統合の方法

### 2.1 突き合わせの単位

- 帯外204枚のIDごとに、#376 の段階・区分・基盤と、#375 の段階・必要基盤・効果要約を並べた。
- 効果の構造は `data/bga-card-specs/` がある59枚について仕様JSONを確認し、無い145枚は
  台帳（費用・前提・種別・印刷点）とwikiの効果文で確認した。
- 段階の差は **78件**。内訳は「実装済みの扱いの差」25件と「段階の実質的な差」53件。

### 2.2 裁定の規則（優先順）

1. **段階の優先順を守る。** 段階1→2→3→4→段階外の順で最初に該当した1つを採る。
   段階3の条件（家の種類・部屋・住居・帰宅）を満たすカードを、段階4の「2サイト」だけで
   段階4にしない。
2. **カードスペース自体は個性に数えない。** 自分専用・全員用スペースであることは段階2の
   共通機構に置き、使用回数・累積・リセット・他者の支払いを個性として判定する。
3. **家・部屋・家族・帰宅は段階3。** 改築経路の許可・軽減も「家の種類」への効果として段階3に置く
   （#370 の C013 / D013 / C123 と同じ扱い）。石の家を条件にするだけのカードも段階3。
4. **OR費用は本当に選択かで判定する。** 費用の区切りがカンマ（AND）なら段階1にしない。
5. **実装済みは段階と別軸。** #370 と同じく「実装済」を独立区分とし、#375 が付けた段階は注記に残す。

### 2.3 裁定の結果

| 区分 | 件数 | 採用した側 |
|---|---:|---|
| 段階の実質的な差 | 53 | #376 43 / #375 10 |
| 実装済みの扱いの差 | 25 | 実装済（#375 の段階を注記） |
| **合計** | **78** | |

- #376 を採った主な理由は、出したとき＋反復トリガー／ラウンド予約＋開始時／在庫＋取り出しを
  「2サイト」として段階4にする点（37件）と、石の家・部屋コストを段階3にする点（4件）。
- #375 を採った主な理由は、段階3優先（改築・家の種類・家族・帰宅）を段階4や段階外より先に置く点
  （9件）と、E075 の費用がANDである点（1件）。
