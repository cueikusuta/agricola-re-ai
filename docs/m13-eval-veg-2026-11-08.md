# M13/#106 実験: 野菜優先の評価変種 `eval_veg`（結果: 2人戦で有意に悪化、4人戦で差なし）

実施日：2026-11-08。対象：カードなし、追加アクションスペースOFF。比較対象は既存 `EvaluationPolicy`（以下 `eval`）。**本実験は既定AIを変更しない。** 変種は明示的に選んだときだけ使う。

> 本ファイルは実験記録であり、強さの合否判定ではない。M13の正本は `docs/roadmap-m7-onward.md` 3節、既存の分析は `docs/ai-loss-analysis.md`。

## 1. 仮説と根拠

`docs/ai-loss-analysis.md` の順位別診断で、2人戦の `no_vegetables`（野菜を持たずに終局）が最も大きい負の相関（1位率 − 非1位率 = **−0.377**、2026-11-06の300試合）だった。2026-11-08に別seed（930000から150試合、eval、2人/4人）で再計測しても **2人戦 −0.347** で最大だった。

得点表では穀物と野菜のカテゴリは同形（0個 −1点、1〜4個で1〜4点）で、野菜はパン焼きなしでそのまま食料にできる。それにもかかわらず現行評価は供給1単位目を

- 穀物：`marginal(grain, 1, 8.0, 2.0)`
- 野菜：`marginal(vegetable, 1, 7.0, 2.0)`

と、**野菜を穀物より低く**見積もっている。そのため `VegetableSeeds`（prior 25）は `GrainSeeds`（prior 23）より状態価値で劣り、実際の選択でも負けやすい。仮説は「野菜の1単位目を穀物と同じ価値にすれば野菜を取る頻度が上がり、順位が改善する」。

## 2. 変更

`EvaluationVariant::VegetableFirst` を追加し、`evaluate_player` の野菜項だけを `marginal(vegetable, 1, 8.0, 2.0)` にした。それ以外（prior重み、state重み0.5/2.0、他の特徴量、詳細生成、探索）は変更していない。

- 既定の `EvaluationPolicy` は `EvaluationVariant::Baseline` のままで、**従来とバイト単位で同じ挙動**（回帰テスト `evaluation::projection_tests::the_hoisted_baseline_keeps_the_per_action_ranking` が維持）。
- 変種は `--candidate eval_veg` として `paired_eval` からのみ到達できる。

## 3. 方法

- 実装：`paired_eval`（同一seed・席ローテーション・両arm共通の相手）。相手は全席 `eval`。
- 2人戦：seed 811000〜、**300ブロック × 2席 = 各arm 600試合**（合計1,200試合）。
- 4人戦：seed 811000〜、**100ブロック × 4席 = 各arm 400試合**（合計800試合）。
- 統計：`scripts/paired_eval_stats.py` のseedブロック単位対応差のpercentile bootstrap 10,000回、95%区間。
- 1手10秒：両armとも探索なしのヒューリスティックで、`eval_veg` は探索予算を持たない。フォールバック機構は既存のまま。
- 環境：Windows 11、`cargo build --release`、ローカル実行。

**実行規模の制約**：当初は1,000ブロック（各arm 2,000試合）とGitHub Actionsでの1,000試合/arm実行を予定したが、本セッションでは大量評価のローカル起動と `workflow_dispatch` の実行が権限で拒否された。以下は**スクリーニング規模**の結果であり、M13の正式受入（1,000試合・未知seed）を代替しない。

## 4. 結果

| 条件 | candidate 首位クレジット | baseline 首位クレジット | 差 | 95%区間（対応差） | games/arm | 判定 |
|---|---:|---:|---:|---|---:|---|
| 2人戦 | 0.4525 | 0.5000 | **−4.75 pp** | **[−7.67, −1.92] pp** | 600 | 有意に**悪化** |
| 4人戦 | 0.2512 | 0.2500 | +0.12 pp | [−2.25, +2.63] pp | 400 | 判別不能 |

補助指標：

| 条件 | 期待順位 cand / base | 得点差（相手平均との差）cand / base | 5pp検出の参考必要ブロック数 |
|---|---|---|---|
| 2人戦 | 1.547 / 1.500 | −0.773 / 0.000 | 204 |
| 4人戦 | 2.507 / 2.500 | −0.212 / 0.000 | 51 |

- 2人戦の対応差の95%区間は**0を跨がず**、負の側にある。したがって「野菜の1単位目の価値を穀物と同等に上げる」は、少なくとも `eval` 相手の2人戦では**改善ではなく悪化**である。
- 4人戦は区間が広く、改善も悪化も判別できない（判定保留）。
- 首位率 +5pp の目標は達成していない。達成したとは記載しない。

## 5. 解釈と次に試すこと

野菜の取得頻度ではなく**食料効率**が制約になっている可能性が高い。穀物は1単位からパンで複数食料になり得る一方、野菜は1単位＝1食料で、しかも種を植えて収穫するまで手番が要る。1単位目の価格を上げると、序盤の食料確保を野菜に置き換えて手番と食料の両方を失う、という説明が結果と整合する。

この負の結果を受けて、`eval_veg` は既定に採用しない。次の候補（未実施）は以下とする。

1. **食料バッファ変種**：収穫までの距離に応じて要求食料を+1する。`docs/ai-loss-analysis.md` 5.3 の候補。`begged` 率と最下位得点で評価する。
2. **野菜価値の条件化**：かまど・暖炉など調理手段を持つ場合、または食料安全度がしきい値以上の場合だけ野菜価値を上げる。単純な一律引き上げが悪化したことの直接の検証になる。
3. **家族増員の遅れ**：2人戦で `late_third_worker` の負の相関が −0.20 残る。食料制約下での部屋建設順序を分けて測る。

いずれも同一seed・同一座席・同一相手での対応比較を前提とし、既定AIを変更する前に本ファイルと同じ形式で記録する。

## 6. 再現手順

```bash
cargo build --release --locked --bin paired_eval
./target/release/paired_eval \
  --players 2 --seed-start 811000 --block-start 0 --blocks 300 \
  --candidate eval_veg --baseline eval --opponent eval \
  --additional-action-space false --output target/paired-eval-veg-2p.jsonl
mkdir -p target/veg2p/shard-0
cp target/paired-eval-veg-2p.jsonl target/veg2p/shard-0/matches.jsonl
python scripts/paired_eval_stats.py --root target/veg2p \
  --players 2 --seed-start 811000 --first-block 0 --blocks 300 \
  --candidate eval_veg --baseline eval --opponent eval \
  --output target/stats-veg-2p.json
```

4人戦は `--players 4 --blocks 100` に置き換える。正式評価は同じコマンドを `blocks` 1,000（2人戦）に増やし、未知seedでGitHub Actions `Paired AI Evaluation` を `candidate=eval_veg`, `baseline=eval`, `opponent=eval` で実行して行う。
