# ルール解釈記録

実装中に公式ルールと設計の不一致・曖昧さを発見したら、ここに典拠・候補・影響範囲・人間の決定を記録。

- 現状：未判断事項なし（公式ルールの照合は未完了）。

## 2026-11-04 公式付録に基づく確認済み修正

- **畑の得点**：0〜1枚は-1点、2/3/4/5枚以上は1/2/3/4点（Appendix p.11、"Field Tiles"）。初期ドラフトの誤った計算を修正。
- **パン窯**：Clay Ovenは1回のパン焼きにつき穀物ちょうど1→食料5、Stone Ovenは最大2→各4（Appendix p.2、"Major Improvements"）。上限を修正。
- **調理による野菜の食料化**：暖炉は野菜1→食料2、調理場は野菜1→食料3（Appendix p.2）。フリー変換を更新。
- **追加タイル**：4択の1つを選ぶとラウンド中ほか3つも使用不可。林の木材は選ばれなくても保持（Appendix p.8）。

### 追加で公式照合が必要

- パン焼きに複数の改善を同時利用する場合の細部指定を、現在の`bake: u32`から改善ごとの割当へ拡張すること。
- 柵の内部仕切り・牧場の拡張と分割の一般形を実装すること。
- [確認済み] 動物・資源・作物の一般供給は、物理トークンが不足したら代用品を使える。ルール上の有限上限にはしない。

## 2026-11-04 M1追加検証：柵とパン焼き

- **牧場内の分割**：既存牧場を内部柵で分けることは認められる。2016年リバイズド版公式付録 p.7（Fencing）・ルールブック p.8（Animal Husbandry）。完成済みの外周柵を取り壊すことは認められない。`FenceDetailed` は分割後の牧場領域と家畜の配置を明示する。
- **パン焼き時の設備選択**：公式ルールブック p.10・付録 p.2。交換はいつでも自由な「パン焼き」アクションがある時だけ。各Clay Ovenは1粒を食料5、Stone Ovenは最大2粒を各食料4にする。複数設備の選択は新しい `BakeAllocation` で外部ポリシーから明示できるようにする。
- **追加したモデル**：`SowDetailed`・`BuyDetailed`。旧来の整数 `bake` はテスト互換のため残し、決定的な割当を実行する。
- **未解決**：入手した動物をどの牧場に割り当てるかと繁殖後の移動のルール細部、カードフックと収穫ポリシーのログ完全再現性は引き続き受け入れ前の検証対象。


## Issue #27: 大きな進歩の購入方法（2016改訂版）

- 公式付録 p.2「Major Improvements」：全10枚の建築費・得点・工房変換。かまど（Fireplace）を保有していても、調理場（Cooking Hearth）を**建築費で購入**できる。既存のかまどを返却するのは代替手段であり強制ではない。
- 新しい `Detail::BuyWithMode` は `PurchaseMode::Pay` と `PurchaseMode::Exchange(Fireplace2/Fireplace3)` を明示できる。従来の `Detail::Buy` は互換性のため自動交換を継続。
- 2016年版の付録 p.2 は https://www.lookout-spiele.de/upload/en_agricolare.html_Appendix_Agricola-RE_EN.pdf 。カード本文や画像を公開リポジトリへ含めない。

## 2026-11-04 公式ルールブックp.12：一般供給の有限性

- 公式ルールブック末尾の「Number of Components」は、各プレイヤーの**人5、厩4、柵15**だけを意図的な個数上限とし、それ以外の共有トークンが不足した場合はgoods tilesまたは代用品を使用できると明記する。
- よって羊18/猪15/牛13、木30/粘土24等は同梱の物理的なコマの数であり、ゲーム内の獲得数の上限ではない。シミュレーターでは一般供給を有限化しない。Game::validate は個人コマの上限をチェックする。
- 根拠：https://lookout-spiele.de/upload/en_agricolare.html_Rules_Agricola-RE_EN.pdf p.12、Number of Components。

## Issue #45: 厩の設置場所（2016版ルールブック p.8）

- 「Farm Expansion」で新しい厩を建設できるのは、部屋・畑・牧場タイルのない農場マスだけ。すでに牧場になったマスに厩を後付けするのは不可。
- 逆方向（先にタイルのないマスに厩を建て、後からそのマスを柵で囲う）は合法。囲いの中の厩はその牧場の収容能力を倍増する。
- `build_stable` は `Tile::Empty` のみ受け入れ、`build_pastures` は既存の厩を囲う処理を維持する。失敗時の不変性と順序の回帰テストを追加。
- 根拠： https://lookout-spiele.de/upload/en_agricolare.html_Rules_Agricola-RE_EN.pdf p.8。

## 2026-11-08 M8-2 詳細操作API監査（#109）

対象：`Game::validate_action` / `Game::apply` / `Game::apply_free` と `SimpleDetails` の候補集合。
回帰テスト：`tests/m8_detail_api_audit.rs`（18件、`cargo test --test m8_detail_api_audit`）。

- **確認できた受理**：`SimpleDetails` が作らない詳細も、共通検証器が受理することを確認した。柵の複数牧場（1アクションで2牧場）、畑の任意マス・2マス目以降の隣接要求、部分播種と作物混在、2室+厩の同時建設、牧場/厩/ペット/調理/破棄の混在配置、炉→かまどの順の明示パン焼き、かまどを購入費で買う選択、給餌順序の明示、収穫前の作業取消不能性、フリーアクションの変換・調理・破棄・再配置、播種のみ／新規開墾マスへの播種。
- **確認できた拒否**：重複・非連結・重なり牧場、未接続の2枚目畑、種不足・重複播種、厩の部屋マス設置、牧場の異種混在・頭数不一致、設備の重複使用・炉の能力超過、非炉への即時パン焼き、不正な給餌順序、家畜を増やす再配置。いずれも状態ハッシュ・ログ・使用済みスペースを変えない。
- **回帰**：非既定詳細を含む操作列が `save_json`/`load_json` と `Game::replay` で同一ハッシュになることを確認（状態を改変しない自然な対戦列で検証）。

### 未判断（公式資料の確認待ち。推測で仕様を変更しない）

1. **同一アクションでの非隣接な複数牧場**：現在 `build_pastures` は「新規牧場は既存牧場（または同じアクションの他の新規牧場）と辺で隣接すること」を要求する（`src/engine.rs` の "new pastures must be adjacent" / "new pasture is not adjacent to existing pasture"）。1アクションで離れた2つの牧場を作る操作は受理されない。`docs/design.md` の柵テスト項目に「隣接」とあるため、意図的な制約か実装上の都合かを公式ルール本文で確認する必要がある。影響：離れた牧場を作る人間操作がUIで拒否される。確認先：2016年改訂版ルールブック柵の項、付録 Fencing。
2. **部屋数の上限**：`build_room` と `Game::validate` は部屋数の上限を持たず、得点も部屋数に比例する。公式コンポーネントの部屋コマ数が上限なら不変条件の追加が必要。確認先：ルールブック柵・部屋の項、Number of Components。
3. **調理設備なしの野菜→食料**：`FreeAction::ConvertCrop` は調理設備がない場合も野菜1→食料1を許可する。暖炉・調理場の変換率（野菜1→2／3）は確認済みだが、設備なしの可否は未確認。確認先：付録 p.2。
