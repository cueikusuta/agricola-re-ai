# M2：公開状態の評価関数AI

## 実装内容

- `src/evaluation.rs` の `evaluate_player` はプレイヤーの**公開状態のみ**を特徴量に変換し、`Evaluation` を返す。
  - scoring：現在の公式最終得点表から算出した暫定得点（評価に使用する単位へ係数変換）
  - food_safety：次回収穫までの距離、家族・新生児の必要食料、所持食料の不足
  - family_growth：家族を早期に増やした場合の残りラウンドの行動機会
  - housing：空き部屋と家族増員の可能性
  - farm：種まき済みの作物、牧場容量、調理設備
  - resources：木材・葦・レンガ・石材・穀物・野菜の、閾値付き限界価値
- `action_value` は既存 `SimpleDetails` が提示する合法候補の**即時効果を概算**して、前後の評価差を計算する。厳密なゲーム状態更新ではなく、ルールの正確さは従来どおり `Game::apply` が保証する。
- 差し替え用の `action_value_with_details(obs, space, details)` と `DetailAwareEvaluationPolicy` を用意。別の `DetailPolicy` を使う場合、行動の評価と実行の両方へ**同一の** `DetailPolicy` を渡すこと。M2標準設定は従来の `SimpleDetails` と互換。
- `EvaluationPolicy` は `SpacePolicy` を実装。ランダム性は従来の意思決定用RNGだけを使用し、公開されていないラウンド順・シードを参照しない。家族増員による追加行動の見積もりは現在のラウンドを含めず、次ラウンドから最終14ラウンドまで。

## 実行方法

```bash
cargo run --release --locked -- --eval --seed 42
cargo run --release --locked -- --eval --batch 100 --seed 4200
cargo run --release --locked -- --benchmark 50 --seed 4200
cargo run --release --locked -- --benchmark 50 --seed 4200 --additional-action-space
```

`--benchmark N` は共通Nシードを使い、各シードごとに先後を入れ替えて2試合行う。3比較（貪欲 vs ランダム、評価関数 vs 貪欲、評価関数 vs ランダム）を出力する。勝ち負けは公式スコアと建築資源による同点判定に従い、完全同順位は引き分けとしてカウントする。`left_win_rate` は `(勝利 + 0.5 × 引き分け) / (2 × N)`。平均スコア差も併記する。

`--eval` は全プレイヤーに評価関数AIを使用する。従来の `--greedy`、無指定のランダムAI、ログ・保存・再現性は維持する。`--benchmark` とログ／保存／`--batch` は同時使用しない。

## 評価と限界

- M2で目指す強さの順位は「ランダム ＜ 貪欲 ＜ 評価関数」。順位は**両追加タイル設定**での対戦勝率を計測して判断する。勝率はシードや試合数で変動するため、試合数の少ないユニットテストでは優越性を保証しない。
- 評価は1手の効果を概算するため、複数ターンにまたがる厳密な読み、将来の未公開ラウンドを使った計算、柵の形の最適化、全てのフリーアクション最適化は行わない。これらはM3の探索および今後の細部ポリシー改善の対象。
- 食料安全度は手持ち食料に加え、次の収穫で得られる作物1個/畑、食用の穀物・野菜、所有設備による家畜の調理、工房の1資源変換を「利用可能な食料」の上限値として数える。これは給餌手順を厳密に実行した結果ではなく、繁殖用家畜を食べる可能性も含む。余剰食料の評価には保有食料のみを使い、家畜・資源を余剰食料として重複加点しない。
- 井戸の将来食料を残りラウンド数に応じて評価する。パン焼き・家畜調理の即時効果は設備と家畜の種類で区別し、調理場への交換は旧暖炉の除去と資源不要の扱いを反映する。柵は内部の分割でも新しい柵の本数と家畜配置を近似状態へ反映する。
- 評価専用の近似処理は `Game::apply` の代用ではない。値が正確に一致する必要がある決定的な効果には固定回帰テストを追加し、探索段階で新しい詳細選択ポリシーを使うときは再検証する。
- ルールエンジンは変更せず、M1で検証済みのルール・ログ・保存・状態ハッシュを引き続き使う。

## 重みの検証（2026-11-05）

`prior_weight=0.5`、`state_weight=2.0` を標準設定とする。貪欲AIの行動優先度を補助情報として残しつつ、M2の状態評価差を主に使う。

初期PRに書かれた「貪欲AI相手に400勝0敗」という説明は最新の実測値と一致しないため撤回した。旧コミット `4821607` に対する [CI run 41867506759](https://github.com/cueikusuta/agricola-re-ai/actions/runs/41867506759) では、シード7100・50シード×先後交代で追加タイルOFFが100勝0敗、ONが**99勝1敗**（計199勝1敗）。この値は**旧コミットの参考値**であり、その後の評価関数修正後の結果を示すものではない。

通常CIでは、調整に用いたシード（4200／7100／16800）とは異なる**26000の20シード×先後交代×ON/OFF**の比較を行い、評価関数AIの勝率がそれぞれ60%を超えるか回帰テストでも確認する。調整用シードのベンチマークと独立シードの確認結果はCIログに残す。勝率は測定条件とコミットSHAを必ず添えて報告し、人間相手の強さを保証するものではない。
