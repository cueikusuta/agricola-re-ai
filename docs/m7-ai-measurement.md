# M7：非公開カード下でのAI選択・対戦評価

正本は `docs/design.md`。この文書はM7実装の仕様・検証方法・限界を記録する。公式カード原文・画像は含まない。

## 実装範囲

- `src/mcts.rs`: `Observation` の公開済みカード、自分の手札、相手の手札枚数、公開カード定義だけを使って未公開カードの所在を再抽選する。職業・小改善を別々に無作為割当し、既知カードの重複、所持枚数、公開のプレイ済みカード、カード得点との整合を検証する。非公開ラウンド順序も公開済みのラウンドカードから再抽選する。
- `src/policy.rs`: `CardChoiceDetails` は自分の既知手札から支払い可能なカードだけを比較し、支払い後の資源・印刷得点・条件付き即時効果を自分の状態のコピーに実際にカードを適用して計算する。持続効果の期待価値は残りラウンド数で概算する。合法判定は必ず元のRustエンジンが行う。カードを使わない細部は従来の `SimpleDetails` に委任する。
- `src/evaluation.rs`: 手札のカードプレイ・公開されているカードの行動後効果（既に使ったアクションスペースを条件とするものを含む）・終了時の得点ボーナス・建築費割引を評価用の近似状態に反映する。評価関数と実際の行動生成で同一の詳細決定ポリシーを使う。
- `src/score.rs` の `standings_with_cards` をMCTSとカード対戦計測でも使用し、印刷得点だけでなく終了時のカードボーナスも勝敗・得点差に含める。
- `src/web.rs`: ローカルCPUがカードありモードでカード選択を使う。人間の詳細入力は従来どおり必須。

## ベンチマーク

`--benchmark-cards N` は2人戦・実装済みA/Bの30枚セットを使用し、各シードを席順入替で2回対戦させる。既存の `--benchmark N`（手札なし）とは混同しない。

```bash
cargo run --release --locked -- --benchmark-cards 10 --seed 901
cargo run --release --locked -- --benchmark-cards 10 --seed 901 --additional-action-space
cargo run --release --locked -- --benchmark-cards 2 --seed 901 --mcts-simulations 8
```

通常CIではカードあり比較を**10シード×先後交代＝各組み合わせ20試合**、追加タイルOFF/ON両方で実施する。カードモードでMCTSを評価する場合のみ `--mcts-simulations N` を併用すると、基準の3比較（greedy vs random、eval vs greedy、eval vs random）にMCTS vs evalを加える。計算量が大きいため最初は少ないシードと探索回数から始める。

出力の意味：
- `left_wins` / `right_wins` / `ties`: 正式な得点と建築資源のタイブレークで決まる勝敗。完全同順位だけ引き分け。
- `left_win_rate`: `(left_wins + ties/2) / games`。先後入替済みの得点付き勝率。
- `left_mean_score`、`right_mean_score`: 最終得点の平均。カードの終了時得点を含む。
- `left_mean_margin`: 左側の得点から右側の得点を引いた平均。勝率とは分けて記録する。

対戦結果がシード・探索回数・座席によって大きく変動するため、数試合だけで「上位AIに勝てる」とは判断しない。比較する場合は**コミットSHA、探索回数、シード、追加タイルのON/OFF、全試合数**を併記する。人間との対戦性能は別途評価が必要。

## 探索方式の比較検討（M7時点）

| 方針 | 非公開情報の扱い | 利点 | 欠点・今回の扱い |
| --- | --- | --- | --- |
| 公開状態の評価関数＋カード選択 | 自分の手札・公開盤面のみ | 速く、条件付きカードの即時効果を正確に予測できる | 複数手を読むのは不得意。M7の基準AI |
| 観測ベースの再抽選型MCTS | シミュレーションごとに未公開手札・ラウンド順を再抽選 | 既存MCTSを活用し、公開知識に矛盾しない多数の未来を評価できる | 実行時と探索時の細部ポリシー一致が必須。M7で実装 |
| 情報集合MCTS（ISMCTS） | 観測上等価な状態を同一情報集合で扱う | 相手の見えない手札を前提にした決定の矛盾・戦略融合を減らしうる | 情報集合キー、相手の観測ごとの合法手、利用可能性統計などの設計が必要。M7では**比較検討のみ、正式実装はしない** |

M7では既存MCTSとの互換性、実装の検証容易性、カード配布の非公開性を優先し、再抽選型を採用した。方式間の優劣や「MCTSが評価関数より強い」ことはまだ実測で証明していない。正式なISMCTS導入は、十分なシードで再抽選型と基準AIの差が確認されてから独立Issueとして検討する。

## 品質・再現性と限界

- 非公開情報の使用禁止はAPI境界で保証する。AI政策は `Observation` のみを受け取る。相手の手札と未配布カードを別配置へ差し替えても自分の観測が同じなら、同一乱数から同じ再抽選結果になる回帰テストを置く。
- 全14ラウンドの実ゲームには従来の `Game::apply` を使う。AIの簡易投影は合法手や結果の正本ではない。
- 現在の探索は**観測に基づく再抽選型MCTS**。情報集合ごとの統計・戦略融合等を完全に解決した正式なISMCTSとは主張しない。未公開の過去の効果（井戸の予約報酬など）の再構成も近似であり、将来の研究候補。
- カードの価値は手作りの概算。複雑な発動条件・将来の相互作用・相手の戦略を厳密最適化するものではない。MCTSの勝率改善はベンチマークの実測で判断する。
