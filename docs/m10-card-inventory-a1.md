## 4. 効果カテゴリの分布と、共通処理を作る優先順（A-4）

未実装かつ難易度1〜3のカードをカテゴリ別に数えたもの（1枚が複数カテゴリを持つため合計は枚数を超える）。

| カテゴリ | 未実装（難易度1〜3） | 未実装全体 |
|---|---:|---:|
| ラウンド効果 | 148 | 198 |
| 牧場・家畜 | 117 | 190 |
| 建築・費用 | 113 | 215 |
| 即時獲得 | 112 | 190 |
| 条件・選択 | 96 | 133 |
| 収穫 | 94 | 109 |
| 畑・種まき | 73 | 122 |
| 要分類 | 74 | 82 |
| 資源交換・食料化 | 69 | 89 |
| 終了時得点 | 45 | 51 |
| 手札・カード操作 | 44 | 102 |
| 他プレイヤー | 0 | 92 |

読み方：

- **ラウンド効果／収穫／終了時得点**は既存の `StartRoundGain` / `HarvestFieldGain` / `EndGameBonus` に近い系統で、共通化の費用対効果が最も高い。
- **建築・費用／即時獲得**も `OnPlayGain` 系の拡張で扱える範囲が大きい。
- **牧場・家畜／畑・種まき**は件数が多いが、配置・収容の詳細決定と結びつくため、カード側ではなく `SimpleDetails` 外の合法詳細API（#109）側の整備が先に必要になる。
- **他プレイヤー**は難易度4〜5に集中しており（4〜5が92、1〜3は0）、A-4が警告する「大規模で複雑な抽象化」に当たる。カードIDを増やすためだけに実装しない。
- **要分類**82枚は自動一次分類が失敗した行であり、実装候補として数えてはならない。先に分類の人手確認が必要。

## 5. 再現方法

```sh
python3 scripts/card_inventory_report.py --output card-inventory.json
python3 -m unittest discover -s tests -p test_card_inventory_report.py -v
```

- 台帳の行が重複した場合、未知の `card_type`、未知の `implementation_reference`、不正な難易度は**失敗**させる（分類から静かに消える行を作らない）。
- `official_verification_included: false` を必ず出力し、公式照合済みと誤読できないようにする。

## 6. 未解決と阻害要因

1. **公式照合0枚**：公式カード原文・画像を取得できないため、PR #141 の方法論どおり `verified` へ昇格できるカードは存在しない。これは実装作業では解消できない。
2. **難易度・カテゴリは一次推定**：`difficulty_1_to_5_preliminary` と `effect_categories_preliminary` は自動分類であり、実装順の確定根拠にしない（A005 で分類と実装の不一致が既知）。
3. **4人人数適格が未確定**：`eligible_at_4` が全840行 `unverified` のため、実装済み34枚のうち何枚が4人戦で合法かは決まっていない（#91 のA055疑義も未解決）。
4. **複合4枚**：専用の型と消費制約が必要で、職業/小進歩の40枚ゲートへ加算できない。

これらは #115 / #91 の人間判断または公式資料が必要であり、本ツールは推測で埋めない。
