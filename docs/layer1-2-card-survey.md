### 1.4 OR 費用の基盤要件（Hermes 向け）

- **現状の型**: `CardDefinition.cost: Vec<(Good, u32)>`、`CardSet::can_play` / `card_costs` /
  `play_validate_pay` は**1つの束**を前提にしている。`play.cost` の spec スキーマも
  `array | null` で、OR を表現できない。
- **必要になるもの**:
  1. 費用の「選択肢の集合」（例: `cost_alternatives: Vec<Vec<(Good,u32)>>`）。
  2. どの束を払ったかの選択を `Action` / `Detail` に載せる（`PlayMinor { card_id, payment }` 等）。
     B065 / C040 は**選択が効果に影響する**ため、記録・再演に必須。
  3. 選択がないカードでも、AI の行動列挙（`policy.rs` / `CardChoiceDetails`）が全束を候補に出す。
     固定優先順で自動選択するなら、その規則を `docs/rule-decisions.md` に残す。
  4. A060 は資源の OR ではなく「所有しているかまど／調理場のどちらを返すか」。既存の
     `PurchaseMode::Exchange`（かまど→調理場）とは別の「返却」操作と、対象の CardZone 移動が要る。
  5. `can_play` の前提判定と支払いを「選んだ束」で行い、`validate_action` と `apply` が同じ束を見る。
- **AI 観測**: どの束を払えるかは自分の手札・資源から決まる。相手の費用選択は公開行動なので
  観測に載せてよいが、未公開情報を増やさない。

### 2.3 基盤の記号

| 記号 | 内容 | 現状のギャップ |
|---|---|---|
| **O** | 非アクターの反応スキャン | `dispatch_after_worker` は**アクター本人の played_cards だけ**を走査する。他プレイヤーのカードを `actor != owner` で走査する経路が無い |
| **A** | 全員（自分含む）発火 | 「他者」だけでなく所有者自身の使用でも発火する。`O` の走査対象に所有者を含める必要がある |
| **E** | 副事象イベント | `EventKind` は WorkerPlaced / CardPlayed / RoundStart / Harvest / ClayConstruction / Bake のみ。部屋建設・改築・畑配置・家族増加・進歩の種類・変換カードの判別が無い |
| **P** | アクション前フック | 相手の行動の**前**に支払い・制限を課す経路が無い。`PhaseTriggerData` は事後スキャン前提 |
| **D** | 相手手番中の所有者 PendingDecision | `PendingDecision.player` を所有者にし、`active_player` は相手のまま、解決後に相手のアクションへ戻す Continuation が無い |
| **T** | 資源移動 | 所有者→相手、相手→所有者の支払いを1つの効果で扱う必要がある |
| **L** | 配置指定 | 部屋・厩・畑のセル指定。`Detail::Build` / `Fence` はあるが、反応ウィンドウから呼ぶ経路が無い |
| **Q** | 数量・詳細の露出 | `PhaseTriggerData` に「取った品物の数」「畑セル」「改築先」「進歩の種類」が無い。`Action.detail` も dispatcher に渡っていない |
| **F** | 一発フラグ / ラウンド内スキップ | D157 の「次に」、D134 の「次の配置を飛ばす」を保持する状態が無い |
| **S** | カードが全員用アクションスペース | カードをアクションスペースとして公開・使用・支払いする基盤が無い（§2.5） |

### 2.4 決定の種類の集計（42枚）

| 決定 | 枚数 | 例 |
|---|---:|---|
| なし（自動） | 22 | A050, B143, C144, E066 |
| 単一（任意の支払い・1つ選ぶ） | 12 | A132, A156, C153, C167 |
| 複合（行動付与＋副決定） | 4 | A150, C151, C152, D149 |
| 配置（盤面の指定） | 4 | A128, C149, D128, E148 |

**読み方**: 42枚のうち **34枚（81%）は「なし」か「単一」**で、少ない選択肢の決定で足りる。
盤面の配置指定が必要なのは **4枚**（+ カードスペースの D051 を入れて5枚）だけである。

**AI 実行**: 他人の手番で発動する所有者の決定も、AI 席では AI が解決する。
`PendingDecision.player` を所有者にし、`active_player` は相手のまま、`Observation` には
公開情報（使用されたスペース、取った品物の数、自分の手札・資源）だけを載せる。
人間席だけプロンプトを出し、AI 席の決定を自動スキップして効果を失わせない。
段階1の決定APIは、まず「反応ウィンドウ＋任意支払い＋1つ選ぶ」を用意し、
配置が必要なカードは既存の `Detail::Build` / `Fence` を反応ウィンドウから再利用する形が小さい。
人間とAIの両方が同じ `PendingResolution` を返せる形にする。

### 3.4 段階2の基盤要件

- **カード畑の状態**: カードIDごとの作物・残り数・収穫済みフラグ。公開情報として
  `Observation` に載せ、AI 評価・UI・保存復元・再演の対象にする。
- **畑カウント**: 現在の畑は `Player.farm` の `Tile::Field` だけ。`field_count`、得点、
  カード前提（`MinimumCropFields` 等）、AI 評価のすべてにカード畑を加算する必要がある。
- **種まき・収穫の対象**: `sow` / `harvest_fields` は農場セルを走査する。カード畑を対象に
  するには、播種・収穫の対象を「農場セル」と「カード畑」の列挙型にする必要がある。
  `Detail::Sow` の `Plant { cell: usize }` はセル番号前提なので、カード畑用の識別子が要る。
- **収穫の「最後の作物」**: E068/E069 は最後の収穫で追加効果。既存の「最後の作物」判定
  （A106 など）と同じイベントが必要。
- **新しい作物**: E068 の「木」は既存の `Crop`（小麦/野菜）に無い。播種・収穫・
  食料化・カード参照のどこまで「小麦と同じ」とするかが未確定（§4 Q-2）。
- **保存・ハッシュ**: カード畑は公開状態なので `state_hash` に入れるのが自然だが、
  v5 の再演契約に触れる。台帳と同じく `integrity_hash` のみにするか、v6 化するかの判断が要る。
- **UI/AI**: カード畑の表示、播種先の選択、収穫の可視化。AI の観測から漏らさない。

## 4. 文献でも決まらない点（人間への質問）

以下は wiki の日英を併読しても確定できなかった。推測で実装しない。

### Q-1 (P1) カード畑は農場のマスを占有するか

- 文献の要約: B068/B113/B141/E068/E069 は「このカードは畑1となる」とだけ書く。農場の
  どのマスに置くか、農場の畑タイルとして扱うかは書いていない。
- 影響: 農場マスを占有するなら配置の決定とフェンス/牧場との干渉が増える。占有しないなら
  「カード畑」を別の畑として数えるだけで済む。得点・カード前提・AI 評価の両方に影響する。
- 質問: 公式カード/FAQ で、カード畑が農場の1マスを使うか、畑の数に数えるかを確認したい。

### Q-2 (P1) E068 の「木を小麦のようにまく」の収穫量と種の出所

- 文献の要約: 木を小麦を植えるかのようにまき、収穫できる。最後の木を収穫すると野菜1。
  収穫量（小麦なら1→3）、播種に使う木の出所（ストックから1木か）が書かれていない。
- 影響: 収穫量を1/2/3のどれにするかでカードの強さが変わる。`Crop::Wood` を追加するか、
  既存の `Crop` に読み替えるかも決まる。
- 質問: 公式カード/FAQ の「like grain」の定義（1木→3木か）を確認したい。

### Q-3 (P2) C044 鶏小屋の費用の区切り

- 文献の要約: 「2 木/2 レンガ,1 葦」。2木 **または** 2レンガ＋1葦 なのか、
  2木/2レンガ のどちらか＋1葦 なのかが読めない。
- 影響: OR 費用の選択肢の数と、AI の支払い計画。
- 質問: 公式カードの費用表記を確認したい（点線/スラッシュの区切り）。

### Q-4 (P2) D134 牡蠣食べの「次の人物を飛ばす」は任意か強制か

- 文献の要約: 漁が使用されるたび1点を得るが、そのラウンドの次の人物の配置を飛ばす。
  「得るが」とあるため強制にも任意にも読める。飛ばす人物が無い場合はどうするかも不明。
- 影響: 所有者の意思決定の有無（`なし` か `単一`）と、ラウンド内の手番スキップ状態。
- 質問: 公式カード/FAQ で任意/強制と、人物が残っていない場合の扱いを確認したい。

### Q-5 (P2) B138 / C051 の支払いができないとき

- 文献の要約: 他プレイヤーは取得前に所有者へ食料1を支払わなければならない。
  支払えない場合にそのアクションが違法になるのか、支払いが免除されるのかが書かれていない。
- 影響: 相手の行動の合法性（`validate`）と、AI の合法手列挙。
- 質問: 公式FAQ の「強制支払い」の扱いを確認したい。

### Q-6 (P3) B072 農業愛の牧場は「畑」として得点・カード前提に数えるか

- 文献の要約: 牧場を畑としても扱い、家畜容量が減る。得点時の畑の数やカード前提に
  数えるかは明記がない。
- 影響: 二重用途の数え方。得点・カード前提・AI 評価。
- 質問: 公式カード/FAQ で「畑としても扱う」の範囲を確認したい。

### Q-7 (P3) B113 / B141 の購入・交換した作物はサプライか、カード畑に植えるか

- 文献の要約: 「食料1を払って小麦1を購入」「レンガ0/1/3を小麦1/2/3に交換」とあり、
  その作物をカード畑に置くとは書いていない。通常の「購入」「交換」はサプライに入る。
- 影響: カード畑が空で始まるか、作物入りで始まるか。播種計画と AI 評価に影響する。
- 質問: 公式カード/FAQ で、購入・交換した作物がサプライに入ることを確認したい。

### Q-8 (P3) E144 セールスマンの「その建築資材」の決め方

- 文献の要約: 資材を食料に変換する効果のカードが出た/建設されたとき、その資材1と葦1。
  「その資材」がカードごとに固定か、複数ある場合に選ぶかが不明。
- 影響: 所有者の決定の有無（`なし` か `単一`）。
- 質問: 対象カードの実装時に、変換対象の資材をどう決めるか公式FAQを確認したい。

### Q-9 (P3) D025 / D159 の効果が取得できない

- 文献の要約: 台帳に個別ページ URL が無く、今回の一括取得でも効果文を取得できなかった。
- 影響: 段階1/2 の該当有無を判定できない。
- 質問: 公式カード名・効果の典拠を提示してほしい。分類は保留。

## 5. 結論

- **段階1-A（OR 費用）**: 13枚。すべて「支払い束の選択」で、盤面配置は不要。
  B065/C040 は選択が効果に影響するため、選択の記録が必須。A060 は資源ではなく
  所有進歩の返却選択で、別の CardZone 操作が要る。
- **段階1の総数**: OR 費用13枚 ＋ 他人手番トリガー42枚 ＋ カードスペース型4枚 ＝ **59枚**（重複なし）。
- **段階1-B（他人の手番トリガー）**: 42枚。22枚は所有者の判断なし、12枚は単一選択、
  4枚は複合、4枚は配置。カードスペース型の4枚を別枠にすると、段階1の決定APIは
  「反応ウィンドウ＋任意支払い＋1つ選ぶ」を先に作り、配置は既存 Detail の再利用で足りる。
- **段階2（畑になるカード）**: 5枚。カード畑の状態、畑カウント、播種・収穫の対象、
  最後の作物トリガー、E068 の木作物が主な追加点。B072 と B019/C019/D020 は関連だが別基盤。
- **実装順の提案**: 段階1は (1) 非アクター走査 `O`、(2) 副事象 `E` + 数量 `Q`、
  (3) 反応ウィンドウの `PendingDecision` `D`、(4) 前フック `P` と移動 `T`、
  (5) カードスペース `S` の順。段階2は (1) カード畑の状態と観測、(2) 畑カウント、
  (3) 播種・収穫の対象列挙、(4) 最後の作物、(5) 新作物、の順。
- 本調査は分類と典拠の照合まで。Rust の実装・仕様 JSON・テストは変更していない。
