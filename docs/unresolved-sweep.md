### 0.1 目的

PR #377（分類確定版）、PR #395（台帳・仕様・テスト契約の3者監査）、PR #386 / #387（仕様修正・実装解釈の照合）で

分類文書（`docs/all-cards-classification-final.md`）と仕様データ（`data/bga-card-specs/`）へ反映し、
確定できないものは「何があれば決まるか」まで具体化して残す。

- 仕様がまだ存在しないカード（S-1 範囲・145枚）は、他担当が新規作成中なので**仕様JSONを作らない**。
  結論は本文書と結果ファイルに残す。
- 他担当の進行中PRが同じ仕様ファイルを触っている場合（D082 / D107）も、**反映せず結論だけ残す**。
- 「効果の扱いが決まらないカードは決めない」という依頼条件は維持する。決まった場合だけ値を入れる。

### 1.2 補足（判定の根拠と反映の限界）

- **A-06 の完全一致／以上**は、日本語印刷面の文言差（A135「1/3/6/9あれば」／C135「1/3/6/9以上」）を根拠にした。
  英語一覧は両方とも "still 1/3/6/9 complete rounds left" で区別しないが、C135 は Comp の累積表
  （R12–13→1木、R9–11→2木、R6–8→3木、R6以前→4木）と一致する。A135 に同種の累積表は無い。
- **A-07 は「版差」として確定**した。日本語印刷面は 3/6/9→2/3/4、英語・Comp・AC・公式同型文 B136 は
  1/3/6/9→1/2/3/4。仕様は BGA 仕様（英語面）を正とするため**値を変えない**。JP UI で JP 印刷面を表示する場合は
  別データ（表示用）を持つ必要がある。これは製品判断なので第6章の残件に残す。
- **A-08 の「捨てる」**は公式付録の「next x round spaces」規定（残りが足りなければ残りにだけ置く）に基づく。
  A022 電報（柵の本数を足す）にも同じ規則を適用する。
- **A-12 の A009** は費用が `sheep:1` で表現できる（D009 に `sheep:2` の前例がある）。台帳は `cost=unknown` の
  ままでも仕様側は表現可能だが、台帳と仕様の二重管理（S-6）に合わせて台帳も `sheep:1` へ直すかは別Issue。

### 5.2 補足

- **E-01** は「得点」ではなく「食料」で、しかも「以後職業を出せない」制限が付く。公式の6ステージ定義
  （収穫が R4/7/9/11/13/14）により、残りステージ数は最大5。従来の4区分（最大3）は誤り。
- **E-03** の英語一覧は「カードの上に置く」と訳しているが、日本語印刷面は「捨てる」で、容量は
  「捨てた木の2倍」。木がカード上に残るかどうかは「木全て」を見る効果に影響するため、JP印刷面を採用する。
- **E-05** は「1つ以上の木、レンガ、葦、石、小麦、野菜」を6種すべてと読む。英語一覧の "and" も同じ。
  「いずれか1種類」と読むと条件が緩すぎ、博物館の館長というテーマにも合わない。
- **E-07** の「その建築資材ちょうど1つ」は、変換効果が扱う資材の種類を指す。複数種を扱うカードでは
  E144 の所有者が1つを選ぶ（既定）。この点だけ実装時に確認する。
- **E-09** の4人戦「資材市場」はレンガ1＋石1＋食料1を一度に与える唯一の基本スペース。3人戦の資材市場は
  「レンガ1**または**石1」なので対象外。カード由来の同型スペースは実装時に個別判定する。
- **E-13** の E052 は費用が「葦1＋木1」または「葦1＋レンガ1」のOR束。台帳の `1_葦 + 1 木/レンガ` は
  この意味で正しい。E053 は木1＋石1のAND。E021 は費用羊1・前提羊4で、効果は「子供が欲しい」スペースの
  占有無視。
