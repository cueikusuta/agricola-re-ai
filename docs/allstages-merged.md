# 全段階（段階1〜4）統合版 — 分類・効果・実装準備の確定

## 第0章 この文書の位置づけ

- 対象: `cueikusuta/agricola-re-ai`。ルールの正本は2016年改訂版 Lookout 公式ルール。
- 統合する成果物:
  - **PR #362**（`research/deepai-allstages-readiness`）: 全636枚の分類と段階1〜4の実装準備。
  - **PR #361**（`research/freebuff-allstages-sources`）: 同じ範囲の独立した文献裏取り。
  - **PR #369**（`research/freebuff-allstages-sources-2`）: #361 の第2ラウンド。追加典拠。
- 本PRは文書のみ。コード・`data/bga-card-specs`・テストは変更しない。マージしない。
- 独立レビューの対象。分類と仕様修正候補が実装計画に影響するため。

### 0.1 対象範囲の正規化

| 成果物 | 範囲 | 枚数 |
|---|---|---:|
| #362 | A/C/D/E の 001〜069・121〜168、B の 001〜168 | 636 |
| #361 / #369 | 台帳の全カード（仕様JSON 695枚・台帳840枚） | 695 |
| 本統合 | **#362 の636枚を確定対象**。070〜120 の帯は Hermes 側の範囲として分類しない | 636 |

070〜120 の帯（A/C/D/E）は、#361 が段階1〜4に多数割り当てているが、
実装済みが多く、Hermes 側の基盤・監査と重なる。本統合では**参考**として付録に列挙し、
確定分類には含めない。したがって、#361 の件数（段階1 13、段階2 42、段階3 63、段階4 32）と
本統合の件数は、範囲が違うために直接比較できない。

### 0.2 裁定の原則

1. **段階の割り当て**は #362 §0.3 の優先順（段階1→2→3→4）を維持する。
   同じカードが複数の段階の基盤を必要とする場合は、早い段階に置き、
   深い基盤を「重なり」として記録する。枚数は二重計上しない。
2. **効果の文言**は、公式ルール・公式付録（一次）→ 印刷カード（準一次）→
   非公式コンペンディウム・カードDB（二次）→ 第三者Wiki（三次）の順で優先する。
3. **決められないものは決めない**。公式裁定が無い解釈は、既定値と残件IDを付けて人間確認に残す。
4. **仕様データの修正**（`data/bga-card-specs`）は本PRでは行わない。修正候補として第4章に列挙する。

#### 3.7 段階3の基盤契約（RH / ROOM）

**RH（帰宅フェイズ）** — 帰宅フェイズは「労働フェイズの後に全員の人物を戻す」フェイズで、
収穫のあるラウンドでは収穫の後に来る。カードは次の payload を要求する。

| payload | 使うカード |
|---|---|
| ラウンド番号、収穫の有無 | A053, A058, B139, D018 |
| 戻した人物のスペース（誰がどこから戻したか） | A035（漁）, A152（授業） |
| そのラウンドに得た建設資材の合計 | A053 |
| 使用済みスペースの集合（帰宅開始時点） | A141, C155 |
| 新生児の数・その収穫で戻した新生児 | A035 |
| 部屋数・家族数・住居スロット | A127, D010 |
| 帰宅フェイズの開始／終了の区別 | A029, A141, A151, A157, C155, D010, D018, D052 |

**ROOM（部屋）** — 部屋は「建てた部屋のセル・数・家の種類」と「現在の部屋数・空き部屋・
住居スロット」の2種類の問い合わせを持つ。カードは次の payload を要求する。

| payload | 使うカード |
|---|---|
| 建てた部屋のセル・数（1アクションで複数室） | A014, A021, A123, A167, B087, D123, E127 |
| 建てた部屋の素材（木/レンガ/石）と家の種類 | B111, D123, E049, E168 |
| 現在の部屋数（条件・得点） | B073, B114, B136, C010, C030, C123, C127, D034, E032, E168 |
| 空き部屋（家族が住んでいない部屋） | C021, C024, D021, E168 |
| 住居スロット（部屋＋カード・厩による拡張） | A010, A127, B021, B085, B092, B127, C024, E151 |
| 部屋のコスト・代用・軽減 | A014, A123, B145, C013, C014, C122, C128, D013, D015, D121 |
| 部屋の得点・排他 | C030, C132, D034, E032 |

RH と ROOM は既存の `EventKind` を置き換える提案ではない。`TR-SITE` に
「帰宅」「部屋建設」「部屋数の変化」を足したときに、payload へ何を載せるかを固定する。
