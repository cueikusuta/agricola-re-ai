# M13-A: 現行PUCTを固定基準にしたアブレーション（Issue #219、2026-11-09）

現行mainのPUCT（`PuctConfig::default()`）を固定ベースラインとして、カードなし4人戦で
最大3因子のアブレーションを行う。**PUCT vs MCTSの再証明には戻らない**（+62.8ppは
`docs/m13-runs/2026-11-08-puct-vs-mcts/` の旧対照との歴史的成果）。

## 1. 既存コードと評価基盤の調査（Step 0との対応）

- 探索実装: `src/mcts_puct.rs`（`PuctConfig`）。现行既定 = simulations 32 / depth 2 /
  c=1.5 / prior_temp=3 / value_temp=8 / leaf=terminal / root_limit=0 / final_prior=0。
  これを `puct-s32-d2-c1.5-pt3-vt8-terminal-rl0-fp0` として凍結する。
- 計測入口: `src/bin/paired_eval.rs`。#219以前は PUCT 設定が1系統しかなく、
  candidate・baseline・相手席が同じ設定を共有していた。そのため「候補=改良PUCT、
  baseline/相手=現行PUCT固定」の直接比較が不可能だった。
- Step 0 性能ベースライン（#237/#238, `src/bin/perf_baseline.rs`）との関係:
  Step 0 は clone/validate/apply/探索の単価を読み取り専用で測る基盤であり、本Issueは
  その単価を変えずに**探索パラメータの挙動と計算コストのトレードオフ**を測る。
  本PRは探索エンジン本体・カードエンジン・UIに触れない。
- 評価基盤: `scripts/eval_ablation.py` はarm間比較（control対比）を提供するが、
  baselineとcandidateに同一政策名を許さないため、PUCT対PUCTの直接比較には使えない
  （仕様どおり）。本作業は `paired_eval` 直実行 + `paired_eval_stats.py` で行う。

## 2. 計測入口の最小拡張（本PR）

`paired_eval` に `--baseline-puct-*` 8フラグを追加した。設計は fail closed:

- **1つも指定しなければ** 従来どおり baseline設定 = candidate設定（後方互換）。
- **1つでも指定したら** 8つすべての明示を必須とする。部分凍結（残りがcandidateの
  値へ沈黙追従する事故）を実行前に拒否する。
- `candidate == baseline == puct` は、行ごとに記録される
  `candidate_puct_config_id` と `baseline_puct_config_id` が**実際に異なる**場合のみ許可。
- baseline arm の焦点席とすべての相手PUCT席は常にbaseline設定でプレイする。
  baseline armは鏡像対照（旧PUCT対旧PUCT）として機能する。
- time-budgetedモードでは焦点席の停止規則は壁時計であり、`puct-simulations`は
  読まれない（独立レビューP2）。したがって**simulationsだけが異なる**PUCT対PUCT実行は
  実行前に拒否する。なお相手席は常時その政策自身の既定回数で動くため、ワークフローは
  既定でbaseline側の8フラグを常に渡す（#219以前の再実行では相手フィールドが凍結構成に
  なる点に注意。既往の正式Runは既定構成のため影響なし）。
- 行内のscalar `puct_*`（`puct_c`等）は常に**candidate設定**を指す。baseline armの
  焦点設定は`focus_puct_config_id`で参照すること（下流ツール向けの注意）。
- シャード8化に伴い、dispatchの`blocks`は8以上が必須（小規模検証はローカル直実行）。
- `paired_eval_stats.py` は config ID を行から検証（全行一致、不一致は fail closed）し、
  レポートへ `candidate_puct_config_id` / `baseline_puct_config_id` を転記する。
  旧形式の行（IDなし）も引き続き受理する。

## 3. 再現可能な基準とpilot設計

- 条件: 4人・カードなし・追加タイルOFF・`simulation-capped`・`decision_budget_ms=0`
  ・candidate席はブロックごとに座席交代（paired_eval内蔵）。
- 相手: **旧PUCT固定**（上記の凍結設定、candidate armでは3席すべて、baseline armでは
  鏡像対照含む全体）。
- pilot seed: **971000–971009**（10ブロック、40試合/arm、他用途未使用を確認）。
- 因子は最大3つ（#219の「合法候補・探索効率・prior」に対応する既存パラメータのみ;
  探索コード・合法性チェックは一切変更しない）:

| 因子 | 水準 | ねらい |
|---|---|---|
| `puct_root_limit` | 8, 12 | root候補をprior上位に絞り探索効率を上げる |
| `puct_prior_temp` | 1.5, 6 | priorの鋭さ（softmax温度） |
| `puct_final_prior` | 0.5, 1.0 | 最終root選択への1手評価のanchoring |

  （`--puct-prior-temp 6`のみ変更）対 凍結baseline `puct-s32-d2-c1.5-pt3-vt8-terminal-rl0-fp0`。

- 条件: 4人・カードなし・追加タイルOFF・simulation-capped・32 sims・depth 2・全席PUCT
  ・baseline/相手は凍結現行PUCT（GitHub Actions `paired-eval.yml` workflow_dispatch、8シャード）。
- 判定基準（採用条件）: 点推定 ≥ **+5pp**（現行PUCT比の目標）かつ
  seedブロックbootstrap95%CIの下限 > 0。**満たさなければ採用しない**。

## 7. 限界

- カードなし限定。4人カード・ドラフトはM10/M11の条件が整うまで対象外。
- 現行PUCTとの差は**探索パラメータのみ**。評価関数・ロールアウト・合法性は不変。
- pilotの数値は強さの主張に使わない。座位ローテーション付き1,000/armでのみ判定する。
- M14のG0〜G3ゲートには影響しない（本IssueはM13の枠内）。
