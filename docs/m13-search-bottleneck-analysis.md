# M13 探索AIのボトルネック解析と限定改善（Issue #106）

更新: 2026-11-08。対象は既存 M7 `MctsPolicy` と `PuctPolicy`。**強さの改善は主張しない。**
本docが報告するのは (a) 計算コストの内訳、(b) 挙動を変えない小規模高速化1件、(c) 敗因診断の集計、
(d) 次に試すべき実験の優先順位である。首位率+5ポイントの目標は未達のままであり、M14 G0〜G3も変更しない。

## 1. 前提と制約

- 大規模比較（1,000試合/arm、座席交代、95%区間）は**本作業では実施していない**。
  `AGENTS.md` 12/13 と `docs/ai-experiments-m12-m14.md` のとおり、大量試合はGitHub Actionsの専用ワークフローで
  実行する必要があるが、本セッションではブランチ公開（push）が環境側で拒否されたため、
  Artifactを伴うActions実行を起動できていない（最終報告に記録）。
- したがって本docの数値は**ローカル・スモーク計測**であり、強さの判定には使わない。
- 既存の `src/bin/mcts_profile.rs` を拡張し、`src/bin/ai_diagnostics.rs` を再利用した。新しい探索アルゴリズムは追加していない。

## 2. 計測条件

| 項目 | 値 |
|---|---|
| ビルド | `cargo build --release --locked`（CLIと同一の最適化） |
| 実行環境 | Windows 11、開発PC、単一プロセス（並列なし） |
| カードなし局面 | 2人戦 seed 12345、追加タイルOFF、ラウンド1の手番 |
| カードあり局面 | 2人戦 seed 777、`verified_basic`（実装済みA/Bプール）、追加タイルOFF |
| 探索設定 | MCTS `tree_depth=2`、PUCT 既定（`simulations=32`） |
| 反復 | クローン等は200回、ロールアウト20回、計測は3回実行して中央値 |
| seed | すべて固定。乱数は `ChaCha8Rng::seed_from_u64` |
| 敗因診断 | `ai_diagnostics --players 2 --seeds 40 --seed-start 900000 --policy eval --additional-action-space false` |

コマンド：

```sh
cargo build --release --locked
./target/release/mcts_profile --hotpath --golden > profile.json
./target/release/mcts_profile --search-budget-sweep > budget.json
./target/release/ai_diagnostics --players 2 --seeds 40 --seed-start 900000 \
  --policy eval --additional-action-space false --output diag.jsonl --summary-output summary.json
```

単位はµs、1呼び出しあたり。`apply` は `apply_with_plans` 内のトランザクション用クローンを含む。

| 構成要素 | カードなし | カードあり | 倍率 |
|---|---:|---:|---:|
| ロールアウト1回（探索と同じ `record_events=false` の局面） | 1,645 | 9,623 | 5.8× |
| ロールアウト1手あたり | 52.8 | 284.3 | 5.4× |
| 評価関数の行動選択1回（合法手全体） | 15.6 | 61.8–89.2 | 4.0× |
| `apply` 1手（カードあり局面） | 2.6 | 17.0–23.4 | 8.7× |
| `Game` クローン | 0.76 | 5.9 | 7.8× |
| `Observation` 生成 | 0.27 | 2.8 | 10.6× |

| 詳細生成（`CardChoiceDetails` / `SimpleDetails`） | 0.01 | 2.1 / 2.5 | — |
| 局面サンプリング（`sample_game`） | 8.1 | 45.7–48.8 | 5.7× |
| 1シミュレーション（MCTS, 32回平均）※ | 2.15 ms | 8.2–9.1 ms | ~4× |
| 32シミュレーションのヒープ割当回数 | 1,360,215 | 9,187,110 | 6.8× |
| 32シミュレーションのヒープ割当バイト | 72.4 MB | 435.7 MB | 6.0× |

※ カードあり局面の「1シミュレーション」だけは、変更前のプロファイラがカードありの決定を計測していなかったため
**変更後の実測**である。他の「変更前」列は `artifacts/profile-before.json`（変更前バイナリ、3回ではなく1回）に基づく。
時刻依存の値は±10%程度ばらつく前提で読む。

**計測上の発見（手法のバグ修正）**：当初ロールアウトを「実ゲーム（`record_events=true`）」で計測していたため、
イベントログのJSON生成と状態ハッシュが計上され、探索より5倍以上高く出ていた。探索は
`sample_game` が `record_events=false` にした局面をプレイするので、**サンプリング後の局面で計測する**よう修正した。
この修正前後の数値を混ぜてはいけない。

## 4. ボトルネックの順位

1. **ロールアウト（1シミュレーションのほぼ全時間）**：カードなし 1.65ms、カードあり 9.6ms。
   1手あたりで見るとカードありは5.4倍。内訳は「評価関数の行動選択（合法手数分の投影）」と
   「`apply` のトランザクション用クローン」と「カード効果処理」。
2. **評価関数の行動選択がカードありで支配的**：合法手8–9件それぞれについて
   `project_action`（`Player` の複製）とカード終了時得点の再計算を行う。旧実装はさらに
   **合法手ごとに `CardSet` を作り直して全カード定義を複製していた**（後述の改善で除去）。
3. **`apply` のたびに `Game` 全体をクローン**：カードありでは `card_set`（34定義）と `log` の複製が効く。
   カードなし0.76µs／カードあり5.9µs。
4. **ヒープ割当の多さ**：32シミュレーションで最大436MB。1シミュレーションあたり約13.6MBを確保しており、
   アロケータとキャッシュに不利。
5. **同じ予算で得られるシミュレーション数**（変更後の実測、カードなし）：
   1秒600回、3秒1,744回、5秒3,018回、**10秒6,016回**。カードありは1シミュレーション約9msなので
   10秒で**約1,100回**にとどまる。カードありモードで探索が弱い理由の少なくとも一部はここにある。
6. 局面サンプリング（`sample_game`）はカードありでも1シミュレーションの約0.5%で、優先度は低い。

## 5. 実装した改善（挙動不変の高速化）

対象：`src/cards.rs`・`src/evaluation.rs`。

1. `cards::end_game_bonus_for_definitions(&[CardDefinition], &Player)` を追加し、`end_game_bonus(&CardSet, ..)` を
   その薄いラッパーにした。評価関数は `Observation` が持つ定義スライスを**借用**し、
   合法手ごとに `CardSet` を作り直して全定義を複製する処理を廃止した。
2. `WeightedEvaluationPolicy::select_with_details` で、候補に依存しない項
   （状態評価 `before` と自分のカード終了時得点）を**1回だけ**計算し、
   `action_value_with_baseline` へ渡すようにした。

**挙動が変わらないことの確認**：`mcts_profile --golden` で 2人戦 seed 0..7 × {評価関数, MCTS16, PUCT32} と
カードあり局面 seed 0..3 の選択手を変更前後で比較し、**完全一致**を確認した。
固定seed再現の要件（`AGENTS.md` 8）に影響しない。さらに
`borrowed_definitions_give_the_same_end_game_bonus_as_the_card_set` と
`the_hoisted_baseline_keeps_the_per_action_ranking` を追加した。

**効果（同一マシン・同一seed、変更前→変更後）**：

| 指標 | カードなし | カードあり |
|---|---:|---:|
| 32シミュレーションの割当回数 | 1,360,215 → 971,847（**−28.5%**） | 9,187,110 → 6,872,139（**−25.2%**） |
| 32シミュレーションの割当バイト | 72.4MB → 47.3MB（**−34.8%**） | 435.7MB → 318.4MB（**−26.9%**） |
| ロールアウト1回の割当回数 | 38,167 → 27,385（−28.2%） | 295,916 → 221,609（−25.1%） |
| 評価選択1回 | 15.6 → 9.6µs | 61.8–89.2 → 50.9–87.1µs |
| 1シミュレーション | 2.15 → 1.50–1.86ms | 8.2–9.1ms（有意差は取れず） |

割当回数は決定的なカウンタなのでノイズがない。時間はWindows上で±10%程度ばらつくため、
「カードありの時間短縮は確認できたと言わない」と明記する。時間固定比較（`--search-budget-sweep`）は
カードなしで秒あたり約600シミュレーションであり、変更前の1シミュレーション単価（2.15ms → 約465回/秒）から
**同予算で約+29%のシミュレーション**に相当する（別実行のため参考値）。

## 6. 敗因診断（`ai_diagnostics`、2人戦・カードなし・評価関数・40試合）

| フラグ | 1位の発生率 | 非1位の発生率 | 差 |
|---|---:|---:|---:|
| 野菜なし | 27.5% | 67.5% | **−40.0pt** |
| 3人目の家族が遅い | 37.5% | 62.5% | **−25.0pt** |
| 家畜なし | 0.0% | 22.5% | −22.5pt |
| 農場の未使用マスが多い | 12.5% | 32.5% | −20.0pt |
| 物乞い | 0.0% | 10.0% | −10.0pt |
| 牧場なし | 0.0% | 5.0% | −5.0pt |
| 空き部屋 | 17.5% | 15.0% | +2.5pt（信号なし） |

平均得点は1位24.2点／2位19.2点で、人間の目安（2人で45〜50点）とは大きく離れている。
これは**相関の記述**であり因果ではない。ただし「野菜・家族増員・家畜・農場の埋まり」が
負けと強く結びつくため、次の実験候補としてはこの4系統を優先する。

## 7. 優先順位付きの次の実験候補

| 優先 | 施策 | 根拠（本docの計測） | 見込み | 必要な検証 |
|---:|---|---|---|---|
| 1 | カード定義を共有（`Arc` 等）して `Game`/`Observation` のクローンを軽くする | カードありでクローン5.9µs・観測2.8µs・`apply` 17–23µs | カードありモードの1シミュレーションを15–25%短縮できる可能性 | 保存・再演の互換、serde、固定seed再現。**高リスク変更なので独立レビュー必須** |
| 2 | 家族増員のタイミングを評価関数で明示的に強化（診断で−25pt） | 3人目の家族が遅いと負けに強く結びつく | 首位率への寄与が最も期待できる | 1,000試合/armの座席交代比較（Actions） |
| 3 | 野菜・家畜の終盤価値を上げる（診断で−40pt/−22.5pt） | 野菜なしが最大の負け相関 | 中〜大 | 同上。過学習を避けるためvalidationで重み決定 |
| 4 | ロールアウト内の候補数をビームで制限（合法手全てを投影しない） | 評価選択が8–9候補×投影 | 1シミュレーションの20–30%短縮の可能性 | 探索の質が落ちないことの同一予算比較 |
| 5 | `sample_game` の配布→上書きをやめる | カードあり45–49µs/シミュレーション（0.5%） | 小 | 固定seed再現、非公開情報の非干渉 |

優先1は設計・保存形式に触れるため、`AGENTS.md` 14/15 の独立レビュー対象。優先2〜4は
**GitHub Actionsの1,000試合/arm（座席交代・95%区間）**を前提とし、本docのスモーク値で採否を決めない。

## 8. 変更しないと決めたこと

- 報酬・目的関数（首位クレジット／得点差）の変更。`docs/ai-experiments-m12-m14.md` §5 の実験計画に従い、
  M13の比較実験として別Issueで扱う。
- 探索アルゴリズムの置き換え（MCTS→PUCT等）。PR #175 の同一予算比較（+1.0pp、目標未達）を履歴として保持し、
  本作業では再測定しない。
- 大規模学習。M14 G0は未達のまま（1,000試合/armのArtifactが無い）。
- `docs/m13-search-time-control.md` の時間予算仕様。変更していない。
