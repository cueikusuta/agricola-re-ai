# M10 カード公式照合パイロット（Issue #115 / #105）

更新: 2026-11-08。**照合結果ではなく、照合のための証拠整理である。`verified` は0枚のまま。**
公式カード原文・画像・全文は収録しない（`AGENTS.md` 6）。効果の記述は「リポジトリ内の実装が何をするか」と
「一次台帳の予備分類」に限り、公式の文言を再現しない。

## 1. 目的と限界

- 840枚の台帳は存在するが、`docs/card-catalog-ae-audit.csv` の `review_status=verified` は**0枚**。
- 本パイロットは、**実装済みカードと未実装カードを混ぜた16枚**について、
  「台帳の予備分類」「現行Rust実装」「両者の差異」「必要な一次資料」を1枚ずつ突き合わせる。
- この自動環境には公式印刷カード・公式PDFがなく、非公式一覧は `secondary_catalog` として `verified` の根拠にできない
  （`docs/card-catalog-official-sources.md` §1–2）。したがって**昇格は行わず**、確認すべき箇所を具体化する。
- 対象16枚の `review_note` に本docの節番号を記録し、`review_status` と `eligible_at_*` は変更しない。
- 配布可能枚数（40+40）とAI評価への影響は本パイロットでは扱わない。**未検証カードは配布対象に加算しない。**

## 2. 選定理由

| 区分 | 枚数 | 対象 | 理由 |
|---|---:|---|---|
| 優先監査（#115指定） | 3 | A005, D159, B095 | A005は実装と予備分類の不一致が疑われる、D159は英名欠落、B095は実装済みで照合の型見本 |
| 複合種別 | 4 | A060, D025, D059, D060 | 40+40ゲートへ機械加算できない型。効果・人数・種別の確定が前提 |
| 実装済みの型別見本 | 7 | A012, A032, A038, A063, A067, A133, B142 | 実装と予備分類の突合で、記録漏れ（条件・人数）を検出する |
| 未実装・低難度 | 2 | A120, D159 | 次の実装候補。照合が済めば40+40へ寄与する |

## 4. 1枚ごとの詳細と、次に確認する一次資料

以下は全カード共通で「公式印刷カード（`printed-card:<ID>:edition-2016`）」または
「公式PDF（`official_pdf` + 該当ページ）」のいずれかを必要とする。非公式一覧は根拠にしない。

### 4.1 A005（小進歩・優先）
- **現行実装**：`src/cards.rs` の `verified_immediate_resource_cards`。コスト食料1、得点0、
  効果 `OnPlayGainPerStored { stored: Clay, divisor: 2, good: Clay, amount: 1 }`。
  テスト `a005_clay_bonus_tracks_two_clay_per_reward`（粘土5→7、食料を支払う）。
- **差異・疑義**：予備分類は「手札・カード操作」「他プレイヤー」を含むが、実装は自分の粘土収支のみ。
  効果の対象・条件・上限が実装と一致するか不明（`docs/four-player-card-rollout-m10.md` の指摘）。
- **確認項目**：①費用 ②獲得量の計算単位（2につき1か、別の区切りか）③上限・端数 ④他人への影響の有無
  ⑤人数適格 ⑥得点。
- **難易度**：予備5。一次資料で上記が確定すれば、既存 `OnPlayGainPerStored` の数値変更で足りる可能性がある。

### 4.2 D159（職業・優先）
- **現行実装**：なし（`implementation_reference` は未実装）。
- **差異・疑義**：`name_en` が空欄。日本語名のみで効果を推測しない。予備分類は「資源交換・食料化」。
- **確認項目**：①英名 ②費用 ③交換レートと回数・タイミング ④人数適格 ⑤得点。
- **難易度**：予備3。交換系のフックが既にあるため、確定後の実装は小さい見込み。

### 4.3 A120（職業・未実装・低難度）
- **現行実装**：なし。予備分類は「即時獲得／ラウンド効果」。
- **確認項目**：①使用条件（職業の枚数・家の材質など）②即時獲得の内容 ③ラウンド開始効果の回数と終了条件
  ④人数適格。
- **難易度**：予備1。`OnPlayGain` と `StartRoundGain` の組合せで表現できる見込みが高いが、
  「実装できる」ことと「公式に正しい」ことは別であり、照合後に実装する。

### 4.4 複合種別4件（A060 / D025 / D059 / D060）
- **現行実装**：いずれも未実装。`card_type_normalized = multi_type`。
- **差異・疑義**：`docs/draft-protocol-m11.md` §2 のとおり、複合種別は公式照合と専用制約が整うまで抽選対象から除外。
  40+40の「適法に配れる枚数」へも加算しない。
- **確認項目**：①どちらの種別として配布・プレイするか（または両方か）②大進歩として購入市場に置くか
  ③コストと得点の計上先 ④人数適格。
- **難易度**：予備5。カード基盤の `CardKind` 拡張か、2段階の演奏経路のどちらかを選ぶ設計判断が必要で、
  1 Issue 1 PRの範囲では完結しない可能性が高い。

### 4.5 実装済み見本（A012 / A032 / A038 / A063 / A067 / B061 / B095 / A133 / B142）
- 一覧表のとおり、**実装が前提条件や人数制限を持つのに台帳の予備分類・人数適格が未確認**という記録漏れが3件
  （A038 の羊5頭、A133 と B142 の3人以上）検出された。台帳側の `eligible_at_*` を推測で埋めないため、
  ここでは「実装が主張している条件」として記録し、`unverified` を維持する。
- また A005・A032・A063 は予備分類と実装の効果系統が食い違う。予備分類は自動推定なので誤りの可能性もあるが、
  **どちらが正しいかをリポジトリ内だけで決めない**。
- これら実装済みカードは `verified_basic` 2人プリセットに含まれる。プリセットは「実装済み」の意味であり、
  「公式照合済み」ではない（`src/cards.rs` の節コメントと `docs/card-catalog-method.md` の区別を維持）。

## 5. 実装難易度の再評価と次の一手

| 難易度 | 枚数 | 例 | 既存フックでの実装見込み |
|---|---:|---|---|
| 1–2 | 4 | A120, D159, A012, A038 | `OnPlayGain` / `Passive` / 終了時得点の数値追加で足りる可能性 |
| 3 | 8 | A067, B061, B095, A133, B142 | 既存variantの組合せ。条件・人数の確定が前提 |
| 5 | 4 | A005, 複合4件 | 効果の意味確定、または種別基盤の設計判断が必要 |

1. **公式資料にアクセスできる人間による確認**（本docの §4 の確認項目を上から埋める）。これが唯一の `verified` 経路。
2. 確認済みカードから `src/cards.rs` へ実装し、`tests/...` に個別効果テストを追加（#105）。
3. 実装枚数が増えても、`docs/card-catalog-ae-audit.csv` が `verified` になるまで 40+40 へは加算しない。
4. 複合種別4件は `#105` の40+40とは別の設計Issueに分離する（種別基盤の変更を伴うため）。
