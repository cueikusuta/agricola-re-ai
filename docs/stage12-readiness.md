### 0.2 基盤への期待（この文書で使う記号）

「基盤が着地したら」の内容をカードごとに書けるよう、次の記号で期待を固定する。
**これは Hermes 側の設計を確定させる指示ではなく、カード実装が要求する契約の一覧**である。

| 記号 | 期待する契約 | この文書での使い方 |
|---|---|---|
| **PS** | 公開状態の単一正本（PublicState 集約） | カード上の公開状態、使用済みスペース、累積量、公開マーカー、スキップ状態を `PublicState` に置き、`Observation` へ射影する。保存・再演・状態ハッシュの対象を一意にする |
| **TR-SITE** | トリガーサイト軸（EventKind＋payload） | 「何が起きたか」を型で表す。使用スペース、取った品物と数量、建てた部屋、改築先、置いた畑セル、増えた家族、出した進歩の種別などを payload に載せる |
| **TR-PHASE** | 解決フェーズ軸（Before / After / Interrupt と所有者範囲） | 同じサイトでも「前フック」「事後効果」「所有者の割り込み決定」を分ける。所有者自身の発火（all）と他人のみ（other）を別フラグにする |
| **SC** | 走査範囲の段階化 | 現在の「アクター本人のカードだけ」から、`other`（他プレイヤー）→ `all`（自分を含む全員）→ `pre`（相手の行動前）へ段階的に広げる。カードごとに必要な段階だけを要求する |
| **DEC** | 相手手番中の所有者 PendingDecision | `PendingDecision.player` をカード所有者にし、`active_player` は相手のまま、解決後に相手のアクションへ戻す Continuation を持つ。AI 席も同じ経路で解決する |
| **DEF** | 定義の正本化 | 費用の選択肢、前提、効果の型、変換対象、畑能力、パン焼き能力などをカード定義の型付きデータにする。効果文の再解析を実行時に行わない |
| **LOG** | 記録・再演 | 選んだ支払い束、返却した進歩、選んだ作物、置いたセル、選んだ組を `Action` / `Detail` / イベントログに残す。固定シード再演で同一状態になる |

**2軸の読み方**: `TR-SITE` が「どのイベントか」、`TR-PHASE` が「そのイベントの前か後か、誰の意思決定か」。
この2軸を分けると、同じ「他者が葦原を使った」でも、A128（事後の部屋建設）、B138（使用前の支払い）、
C145（使用後の葦獲得）を別々に登録できる。`SC` はその2軸をどの所有者範囲まで走査するかの段階である。

### 0.3 事実確認の順序と、情報源が食い違ったときの扱い

1. カード画像の費用・効果欄（もっとも具体的。ただし画像から読み取れない略記がある）。
2. 日本語 wiki の個別ページ（効果文と注記）。
3. 英語一覧・英語版非公式コンペンディウム（日英差の検出）。
4. 第三者のオープンソース実装（曖昧な用語の具体的な解釈。公式ではない）。
5. 上記で一致しない点だけを「残る不明点」に残す。**推測で実装しない。**

### 0.4 共通の実装前提

- 他人の手番で発動する効果の所有者が人間の場合、`DEC` で反応ウィンドウを出す。
  AI 席の場合は同じ `DEC` を AI が解決し、決定を自動スキップして効果を失わせない（#355 §2.4）。
- 他人の手番で発動する効果の支払い・獲得は、所有者と相手の両方の資源を動かす。
  `TR-SITE` の payload に「誰が何を取ったか」が無いと、数量条件（5以上、2以上）を判定できない。
- カード畑は農場セルを占有しない「仮想畑」として扱う。農場の15マス・柵・牧場とは独立に、
  カードIDごとの作物と残量を持つ。畑の数には数える（第4章で詳述）。
- 効果の要約は実装の意味を固定するためのものであり、カード原文の転載ではない。

## 第1章 OR 費用のカード（13枚）

### 1.1 この章の結論

- 13枚はすべて「支払い束の選択」を持つ。うち **B065 / C040 は選んだ束が効果を決める**ため、
  支払い選択の記録が必須。A060 は資源ではなく**所有しているかまど／調理場の返却**で、別の CardZone 操作が必要。
- #355 の費用表記のうち、次の3枚はカード画像と一致しないため**この文書で修正**する。
  - **A064**: 正しくは「木材1＋レンガ4」**または**「石材2」。第2束に木材1は付かない。
  - **C044**: 正しくは「木材2＋葦1」**または**「レンガ2」。葦は両方の束には付かない。
  - **E052**: 正しくは「葦1＋木材1」**または**「レンガ1」。外側の葦1は必須ではない。
- 既存仕様 JSON は A004（cost null）、A064（cost null）、C040/C044（inventory_only の仮効果）、
  C065（cost null）、B141（cost []）などが未整備。実装時に **DEF** で正本化する。
- カード画像で確認した費用の区切りは「スラッシュが束の区切り、＋/カンマが同一束内の合算」。
  C044 と E052 はこの規則で読むと画像の上下段と一致する。

### 1.2 OR 費用の実装契約

1. **DEF**: `cost` を「選択肢の集合」にする。例: `cost_alternatives: Vec<Vec<(Good,u32)>>`。
   空ベクタは無料、`None` は未確認として区別する。既存の `cost: Vec<(Good,u32)>` は
   「選択肢が1つだけのカード」の後方互換表現として残せる。
2. **Action/Detail**: どの束を払ったかを `PlayMinor { card_id, payment }` などに載せる。
   B065/C040 は効果が束に依存するため、**支払い選択をログと再演の入力にする**。
3. **DEC**: 人間が選ぶ場合は `ChoosePayment` を使える。AI は全束を候補にし、
   固定優先順で自動選択する場合も規則を `docs/rule-decisions.md` に残す。
4. **検証**: `can_play` の前提判定と支払いを「選んだ束」で行い、`validate_action` と `apply` が
   同じ束を見る。片方だけ無料になる経路を作らない。
5. **A060 専用**: 返却対象は「所有しているかまど／調理場」から選ぶ。返却先の CardZone と、
   返却後に A060 が何として扱われるか（かまど／調理場／小進歩／大進歩）を定義する。
6. **AI 観測**: どの束を払えるかは自分の手札・資源から決まる。相手の支払い選択は公開行動なので
   観測に載せてよい。A004 の移動先だけは手札であり、相手の手札内容を観測に漏らさない。

### 1.3 カード別

#### A004 幅木（Baseboards）

- **効果（確定）**: 自分の部屋1つにつき木材1を即時獲得。部屋数が家族数より多ければ追加で木材1。
  このカードは自分の前へ置かず、左隣プレイヤーの手札へ移す。
- **#355からの修正**: なし（費用・効果・移動先とも一致）。移動先が手札なので、公開状態と
  非公開情報の扱いを明記する必要がある点だけ補足。
- **実装要素**
  - 状態: なし（即時効果）。カードは `played_cards` に入れず、左隣の手札へ移す。
  - トリガー: `OnPlay`（Before）。部屋数・家族数は play 時点の live state。
  - 判定・決定: 費用の束の選択（食料2 / 小麦1）。効果は束に依存しない。
  - 基盤期待: **DEF**（2束）、**LOG**（支払い束）、CardZone の「左隣の手札」移動。
    **PS** にはカードを置かず、移動先の手札は所有者だけが観測できる。再演は CardZone の
    非公開移動を記録して復元する。
- **テスト**
  - 正常: 食料2でプレイ → 木材=部屋数、部屋>家族なら+1、カードが左隣の手札へ。
  - 正常: 小麦1でプレイ → 同じ効果、支払いだけ異なる。
  - 境界: 部屋数=家族数 → 追加なし。部屋数<家族数 → 追加なし。
  - 境界: 2人戦の左隣、4人戦の左隣、左隣が自分になる設定が無いこと。
  - 秘匿: 移動したカードが他家の観測に出ない。左隣の観測には出る。保存・再演で一致。
  - 不正: どちらの束も払えないときはプレイ不可。片方だけ払えるときはその束だけ合法。
- **残る不明点**: なし（費用・効果とも画像で確認）。CardZone の公開範囲だけ設計判断。

#### A060 東洋かまど（Oriental Fireplace）

- **効果（確定）**: かまど1つ**または**調理場1つを返してプレイする。プレイ後は、いつでも
  野菜→食料4、羊→食料3、牛→食料5の変換ができ、パン焼きでは小麦→食料2の変換ができる。
  1勝利点。小進歩／大進歩の両方として扱う multi-type。
- **#355からの修正**: 分類は正しい。ただし「返却」の対象と返却先、multi-type の意味を確定する必要がある。
- **実装要素**
  - 状態: 所有する `Improvement`（かまど／調理場）と、返却後の improvement market／所有台帳。
    カード上の永続変換能力（`anytime_conversions` と `baking_conversion`）。
  - トリガー: `OnPlay`（Before）で返却。以後はフリーアクション／パン焼きの変換経路。
  - 判定・決定: 返却対象の選択（かまど／調理場のどちらか。両方持つ場合は選択）。
    プレイする束は「返却」の1種類だけで、資源費用は無い。
  - 基盤期待: **DEF**（multi-type、返却費用、変換能力）、**LOG**（返却した進歩）、
    `Improvement` の CardZone 移動、既存のフリーアクション変換への接続。
    **PS** の improvement market に返却した大進歩を戻すか、捨てるかを定義する。
- **テスト**
  - 正常: かまどを返してプレイ → A060 が前へ、かまどが消える。野菜→食料4等が使える。
  - 正常: 調理場を返してプレイ → 同様。パン焼きで小麦→食料2。
  - 境界: かまども調理場も無い → プレイ不可。両方ある → 選択が必須で、選んだ方だけ消える。
  - 境界: 返却した大進歩が市場に戻り、再購入できる／できないの選択。
  - 再演: 返却対象の選択がログに残り、再演で同じ市場・所有状態になる。
- **残る不明点**
  - P2: 返却した進歩の移動先（大進歩は市場へ戻る／小進歩は捨て札か）。
  - P2: multi-type の正確な意味（小進歩としてだけ出すのか、大進歩としても購入できるのか、
    カード参照時に両方として数えるのか）。
  - P3: A060 自身が「かまど／調理場」を前提とする他カードの条件を満たすか。

#### A064 大麦製粉機（Barley Mill）

- **効果（確定）**: 各収穫の畑フェイズに、収穫した小麦畑1つにつき食料1。1勝利点。
- **#355からの修正**: 費用は「木材1＋レンガ4」**または**「石材2」。第2束に木材1は含まない。
- **実装要素**
  - 状態: なし（収穫時に数えるだけ）。
  - トリガー: `TR-SITE = HarvestField`、`TR-PHASE = After`。収穫した畑の作物種と本数。
  - 判定・決定: なし。収穫した小麦畑の数（作物が1以上あり、実際に収穫した畑）を数える。
  - 基盤期待: **TR-SITE** に「収穫した畑ごとの作物」を持たせる。**DEF** で2束の費用。
- **テスト**
  - 正常: 小麦畑2つを収穫 → 食料2。
  - 正常: 小麦畑1つ＋野菜畑1つ → 食料1（小麦畑だけ）。
  - 境界: 小麦畑が空（収穫0）→ 数えない。小麦畑0 → 0。
  - 境界: カード畑で小麦を育てている場合の扱い（第4章の畑カウントに接続）。
- **残る不明点**: なし。

#### B043 料理店（Chophouse）

- **効果（確定）**: 自分が「小麦の種」を使うたび、次の3ラウンドのスペースに食料1ずつ。
  「野菜の種」を使うたび、次の2ラウンドに食料1ずつ。各ラウンド開始時に受け取る。1勝利点。
- **#355からの修正**: なし（費用・効果とも一致）。
- **実装要素**
  - 状態: ラウンドスペース上の予約食料（公開）。カード自身の使用履歴は不要。
  - トリガー: `TR-SITE = SpaceUsed { GrainSeeds | VegetableSeeds }`、`TR-PHASE = After`、所有者自身のみ。
  - 判定・決定: なし。ラウンド番号＋1..+3 / +1..+2 の範囲。14超は置かない。
  - 基盤期待: **TR-SITE** のスペース使用、**PS** のラウンド予約台帳（既存 `delayed_well` 型の
    公開スケジュール）、**DEF** の2束費用。
- **テスト**
  - 正常: 小麦の種 → 次3ラウンドに食料1。野菜の種 → 次2ラウンドに食料1。
  - 正常: 既に予約があるラウンドに加算される。開始時に受け取る。
  - 境界: ラウンド13で小麦の種 → 14だけ。ラウンド14 → 予約なし。
  - 境界: 同じラウンドに両方を使う（カード効果等）→ それぞれの予約が積み上がる。
- **残る不明点**: なし。

#### B048 森の石（Forest Stone）

- **効果（確定）**: プレイ時にこのカード上へ食料2。自分が木材の累積スペースを使うたび、
  カード上の食料1を自分のストックへ移す。石材の累積スペースを使うたび、カード上に食料2を追加。

- **#355からの修正**: なし。
- **実装要素**
  - 状態: カード上の食料数（公開）。0〜増加。
  - トリガー: `TR-SITE = SpaceUsed { wood accumulation | stone accumulation }`、`TR-PHASE = After`、所有者自身のみ。
  - 判定・決定: なし。木スペースでは食料が1以上あるときだけ1移す。石スペースでは常に+2。
  - 基盤期待: **PS** のカード上資源、**TR-SITE** の「木材／石材の累積スペース」判定、

- **テスト**

  - 境界: カード食料0で森林使用 → 獲得なし、カードは0のまま。
  - 境界: 1回のアクションで木材と石材の両方を使う（カード効果）→ それぞれの効果が順に発動。
  - 境界: 追加スペースの林/Copse/Grove も木材累積として数える。東/西採石場も石材。
- **残る不明点**: なし。

#### B065 小麦貯蔵庫（Grain Depot）

- **効果（確定）**: このカードの支払いに木材／レンガ／石材を使った場合、それぞれ次の2／3／4ラウンドの
  スペースに小麦1ずつ。各ラウンド開始時に受け取る。
- **#355からの修正**: なし（選択が効果を決める点も一致）。
- **実装要素**
  - 状態: ラウンド予約小麦（公開）。支払った束の種別。
  - トリガー: `OnPlay`（Before）。
