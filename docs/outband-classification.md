# 帯外（A/C/D/E 070〜120）の分類と実装準備

## 第0章 この文書の位置づけ

- 対象: `cueikusuta/agricola-re-ai`。ルールの正本は2016年改訂版 Lookout 公式ルール。
- 目的: 段階1〜4の分類（PR #370 の636枚）から外れていた帯 **A/C/D/E 070〜120** を、
  同じ形式・同じ段階定義で分類し、実装準備の粒度まで落とす。
- 継承元:
  - **PR #370**（`research/deepai-allstages-merged`）: 636枚の分類・段階定義・基盤記号・残件の形式。
  - **PR #362 / #360 / #355**: 段階1〜4の判定規則と、段階1・段階2の実装準備。
  - **PR #356**（`research/deepai-bonus-remaining-unblock`）: C098 / C099 / D099 / A100 の
    解放条件（G0〜G4）。本帯の該当4枚は**再調査せず参照**する。
  - **PR #361 / #369**: 独立した文献裏取り。帯外カードの一部（後述）はここでも触れられている。
- 本PRは**文書のみ**。Rust・`data/bga-card-specs`・テストは変更しない。マージしない。
- カード効果は、台帳（`data/bga-card-base-ledger.csv`）・仕様JSON（`data/bga-card-specs/`）・
  第三者のBGAアグリコラカード情報wiki（日本語個別ページ）を照合した**自分の言葉の要約**である。
  原文・画像は転載しない。

### 0.1 対象範囲の検算（依頼の211枚 → 実データは204枚）

依頼は「211枚（A/C/D/E の 070〜120）」だったが、台帳 `data/bga-card-base-ledger.csv` の
該当範囲は **204枚**（A/C/D/E それぞれ 070〜120 の 51枚、欠番なし）である。

| A | 51 | 51 | 50（A119 のみ無し） | 1 |
| C | 51 | 51 | 4（C070/C083/C086/C095） | 47 |
| D | 51 | 51 | 5（D078/D079/D081/D083/D084） | 46 |
| E | 51 | 51 | 0 | 51 |
| **合計** | **204** | **204** | **59** | **145** |

- 差の **7枚**は、台帳・仕様JSON・`docs/allstages-merged.md` の付録A のいずれでも特定できなかった。
  考えられるのは (a) 依頼時の概算、(b) 121〜168 の一部を帯に含めた数え方、(c) B デッキの混入。
  本PRは**実データの204枚**を確定対象とし、211枚の内訳は人間の確認待ちにする（BQ-0）。

  **分類文書だけ**を作り、`src/` や Hermes 側の実装ブランチには触れない。

### 0.2 継承した形式（新しく作らない）

段階番号・優先順・記号は #370 §0.2〜0.4 をそのまま使う。

| 段階 | 定義 |
|---|---|
| 段階1 | 費用が「A または B」の支払い候補の選択になっている |
| 段階2 | 他人の手番で発動する／カードが全員用スペースになる／カードが畑になる |
| 段階3 | 帰宅フェイズに発動・条件がある／部屋（建設・数・種類・収容・得点）または住居スロットが効果の条件・対象・発生源 |
| 段階4 | 異なる発動サイトを2つ以上またぐ、または1つのサイトで3操作系以上 |
| 段階外 | 単一サイト・単一操作で、4段階の基盤に依存しない（＝実装しない、ではない） |

判定は **段階1 → 2 → 3 → 4 → 段階外** の順で行い、最初に該当した1つにだけ割り当てる
（#362 §0.3）。重なりは各章の残件に記し、二重計上しない。

基盤の記号も #370 §4.1 の **PS / TR-SITE / TR-PHASE / SC / DEC / DEF / LOG / RH / ROOM / STACK**
と「占有フィルタ」をそのまま使う。本帯だけの追加記号は無い。

**判定の単位（#370 の機械判定を明文化したもの）**

1. サイト＝仕様JSONの `effects[].trigger` に相当するイベント種別。ただし**効果がフェイズそのものを
   実行する**場合は、そのフェイズも1サイトとして数える（例: C072 の畑フェイズ再入）。
2. **常時の軽減・払い戻しは「常時」1サイト**として数える。対象のアクションが複数でも段階4にしない
   （D074 / D082）。
3. **カードがアクションスペースになること自体は共通機構に乗せる**。そのカードの主軸判定では
   個性として数えない（依頼の決定）。ただし他者の使用時に支払いが発生する場合は段階2の軸になる（E081）。

### 0.3 この帯に適用した決定

依頼で確定済みの3点を、そのまま適用した。

1. **OR費用は「支払い候補の選択」**として段階1。資源の選択とは呼ばない。
   進歩を返して出すカード（A060）と同型の**返却・調理による支払い**も、支払い方法の選択として
   段階1の亜型に置く（D082）。
2. **アクションスペースを増やす効果は共通機構**として扱い、そのカードの個性として数えない
   （C104 / D116 / E081）。個性は「使用回数」「累積」「他者の支払い」の側で判定する。
3. **帰宅フェイズに関わる効果は段階3**（帰宅の基盤待ち）。#370 では C051/D051 を段階2＋重なりと
   したが、**この帯では帰宅を主機構とするカードを段階3に置く**（A084 / A100 / C075 / C097 /
   D102 / D107）。any-player 等他の軸を持つ場合は重なりとして記録する。

### 1.2 要点

- **実装済みが13枚**（A075 / A077 / A078 / A080 / A088 / A098 / A099 / A101 / A106 / A110 /
  A116 / A117 / A119）。070〜118 は仕様JSONが揃っており、実装も先行している。
  A119 だけは仕様JSONが無いまま `src/cards.rs` に定義がある（第6章 R-A1）。
- **段階4は7枚**。内容は3型に分かれる。
  - 将来ラウンドへの予約（A074 / A089 / A120）: 厩・改築を起点に予約し、ラウンド開始で回収。
  - カード上在庫の蓄積と回収（A081 / A102）: 累積スペース・固定ラウンド・いつでも購入。
  - 出したとき＋反復トリガー（A096 / A112）: どちらも獲得のみで、点数や配置を伴わない。
- **段階3は7枚**。帰宅2（A084 / A100）、部屋3（A086 / A093 / A111）、住居1（A085）、
  家の種類1（A090）。A100 は #356 の G0+G4 待ちで、本PRでは再調査していない。
- **段階外24枚**の大半は「スペース使用・収穫・畑獲得に対する単発の獲得・変換」である。
  目立つのは次の3枚で、いずれも単一サイトのまま既存基盤の外側の決定を要求する。
  - A094 怠惰な種まき: 種まきを辞退して人物を置く（占有フィルタ＋配置）。既存の横断基盤。
  - A097 新入生: パン焼きの**前フック**で職業を出す（TR-PHASE の Before）。
  - A071 掘り返しシャベル: 「いつでも」の実行窓が未確定（BQ-2）。仕様JSONの effects が空。
- A087 修理屋（木→石の直接改築）と A099 放牧人（牧場の得点）は効果が単純で、
  ROOM の「家の種類」を問い合わせる A090 とは必要基盤が違う点に注意する。

### 1.3 仕様データとの突き合わせ

- 仕様JSONがある50枚は、**印刷点・種別・前提が台帳・wikiと一致**した。
- 効果が空（`effects` 無し）: A071 / A092 / A094 / A097 / A103。
  wiki には効果文があるため、**仕様化待ち**（第6章）。
- `needs_resolution`: A089（14超のラウンド予約）／A094（辞退の窓と占有）／
  A097（1手番・1収穫の制限が英語一覧に無い）／A071／A092／A103。
- A118 樹木庭師は、仕様JSONの第1効果が `frequency: once_per_play` になっているが、
  文言は「各収穫の畑フェイズのたび」であり **`every_harvest` が正しい**。
  さらに「木材2まで」の購入上限が仕様に表現されていない（第6章 R-A2）。
- A111 壁装飾人は、仕様JSONが `optional: true` だが、文言に任意の語が無い（R-A3）。
- A110 仕立屋は `after_clay_construction` 1トリガーで「レンガの部屋の建設」と
  「レンガの家→石の家の改築」の2事象を表しており、payload で区別できない（R-A4）。
